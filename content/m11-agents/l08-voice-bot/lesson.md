## Зачем это нужно

Голосом спрашивают в машине, на кухне, на ходу — там, где печатать неудобно. Голосовой бот из ноутбука курса устроен как цепочка из трёх моделей:

1. **распознавание речи** (speech-to-text, STT): запись → текст. В ноутбуке — сервис SaluteSpeech;
2. **языковая модель** с историей диалога: текст вопроса → текст ответа. В ноутбуке — GigaChat;
3. **синтез речи** (text-to-speech, TTS): текст ответа → звук. Снова SaluteSpeech.

Сервисам нужны ключи, поэтому в браузере их не вызвать. Зато у нас есть настоящая запись из ноутбука, настоящие ответы сервиса распознавания и настоящий диалог с GigaChat — их напечатал сам ноутбук. Начнём со звука.

## Звук — это числа

Микрофон много раз в секунду измеряет давление воздуха. Каждое измерение — **отсчёт**, целое число. Сколько отсчётов в секунду — **частота дискретизации**. Файл WAV хранит отсчёты и заголовок с их параметрами, а модуль `wave` из стандартной библиотеки Python умеет их читать:

```python
with wave.open('recording.wav') as w:
    rate, n = w.getframerate(), w.getnframes()
    print('каналов:', w.getnchannels(), '| байт на отсчёт:', w.getsampwidth(), '| частота:', rate, 'Гц')
    samples = np.frombuffer(w.readframes(n), dtype=np.int16)     # 16 бит: целые от −32768 до 32767
print('отсчётов:', len(samples), '| длительность:', n / rate, 'с')
print('от', samples.min(), 'до', samples.max(), '| пик:', round(np.abs(samples.astype(np.int32)).max() / 32768, 3), 'от предела')
```

Запись моно (один канал), 16 бит на отсчёт, 48 000 отсчётов в секунду — 164 160 чисел на 3,42 секунды. Для речи столько не нужно: распознаванию хватает 16 000 Гц, а это втрое меньше данных. 48 000 Гц выдаёт браузер при записи с микрофона — об этом комментарий в коде записи в ноутбуке.

## Где речь, а где тишина

Громкость коротких кусков звука — **кадров** по 20 мс — меряют среднеквадратичным значением отсчётов (RMS):

```python
x = samples.astype(np.float64) / 32768                  # отсчёты в долях от предела: от −1 до 1
frame = int(rate * 0.02)                                # 20 мс = 960 отсчётов
k = len(x) // frame
rms = np.sqrt((x[:k * frame].reshape(k, frame) ** 2).mean(axis=1))
t = np.arange(len(x)) / rate

fig, ax = plt.subplots(2, 1, figsize=(9, 4), sharex=True)
ax[0].plot(t, x, lw=0.4)
ax[0].set_ylabel('отсчёт')
ax[1].plot(np.arange(k) * 0.02, rms)
ax[1].set_ylabel('RMS кадра')
ax[1].set_xlabel('время, с')
plt.tight_layout()
plt.show()
```

Почти всю запись занимает тишина — фоновый шум с RMS около 0,004. Речь видна как всплески громкости в середине. Найдём её начало и конец: кадры, где громкость не меньше 10 % от самой громкой:

```python
loud = np.nonzero(rms >= 0.1 * rms.max())[0]
start, end = loud[0] * 0.02, (loud[-1] + 1) * 0.02
print(f'речь: от {start:.2f} до {end:.2f} с — {end - start:.2f} с из {n / rate:.2f}')
```

Речь занимает меньше половины записи — от 1,26 до 2,70 секунды. Распознаванию тишина не нужна: если её обрезать, отправлять придётся меньше. Так работает простейший детектор речи. Настоящие детекторы учитывают и спектр звука, и фоновый шум, но идея та же.

## Ответ распознавания

Ноутбук отправлял запись в SaluteSpeech функцией `stt` и печатал ответ сервиса целиком. Четыре таких ответа сохранились:

```python
for r in records:
    if r['kind'] == 'stt':
        resp = r['response']
        feelings = [max(e, key=e.get) for e in resp['emotions']]
        print(f"ячейка {r['cell']}: {resp['result']} | эмоции: {feelings} | статус {resp['status']}")
```

В ответе — список фраз `result`, для каждой оценка эмоций (`negative`, `neutral`, `positive`) и попытка угадать возраст и пол (`person_identity` — здесь «не определено»). Запись `recording.wav` распознана как «Тестовая проверка записи.».

В последнем ответе — две фразы, и вторая пустая. В первой видны ошибки распознавания: «голосовой чат на radio» — в ноутбуке речь о голосовом чате на Gradio. Дальше «potm 3 9 греди» — похоже, тоже названия программ. Языковая модель получит именно этот текст, с ошибками: ошибки звеньев цепочки складываются.

## Ошибка в коде ноутбука

Функция `stt` из ноутбука при успехе возвращает список фраз, а при ошибке — текст ответа сервера:

```python norun
if response.status_code == 200:
    result = response.json()
    return result["result"]          # список фраз
else:
    print("Ошибка:", response.status_code, response.text)
    return response.text             # строка с описанием ошибки!
```

А голосовой чат берёт первый элемент: `answer = self.conversation_predict(rec_speech[0])`. Если сервер ответит ошибкой, `rec_speech` — строка, и `rec_speech[0]` — её **первая буква**. Модель получит вопрос из одной буквы и вежливо на него ответит. Программа не упадёт, а пользователь не поймёт, что произошло. Вторая проблема — `[0]` берёт только первую фразу: если человек сказал две, вторая потеряется. Исправим это в задании: функция будет возвращать понятный результат и при успехе, и при ошибке.

## Голосовой чат и история

Текстовую часть бота ноутбук собрал в класс `AudioChat`: вопрос добавляется в историю как `HumanMessage`, вся история уходит GigaChat, ответ добавляется как `AIMessage`. Первые два вопроса — это распознанная речь из ответов SaluteSpeech выше, третий задан текстом. Учебная версия GigaChat воспроизводит ответы, записанные в ноутбуке:

```python
from langchain_gigachat.chat_models import GigaChat
from langchain_core.messages import HumanMessage, AIMessage

class AudioChat:                                # текстовая часть класса из ноутбука
    def __init__(self):
        self.history = []
        self.llm = GigaChat(credentials='ваш-ключ', verify_ssl_certs=False)

    def conversation_predict(self, message):
        self.history.append(HumanMessage(content=message))
        gpt_response = self.llm.invoke(self.history)          # в ноутбуке: self.llm(self.history)
        self.history.append(AIMessage(gpt_response.content))
        return gpt_response.content

chat = AudioChat()
for question in ['Проверим.', 'Просто удивительно.', 'привет, как дела']:
    print('>', question)
    print(chat.conversation_predict(question))
print('сообщений в истории:', len(chat.history))
```

Модель помнит разговор только потому, что программа каждый раз отправляет ей всю историю (урок 10.3). На «Просто удивительно.» модель отвечает с оглядкой на предыдущий обмен. В ноутбуке модель вызывается как функция: `self.llm(self.history)`. Так писали в старых версиях LangChain; этот способ объявлен устаревшим — вызывайте `invoke`.

Ответ бот озвучивает функцией `synthesize_speech` (голос, формат и текст уходят в SaluteSpeech, в ответ приходит WAV-файл), а интерфейс с кнопкой записи ноутбук строит на библиотеке Gradio. Всё это работает в Colab со своими ключами. Подробнее о технологиях речи — в модуле 12.

## Типичные ошибки

:::mistake Возвращать разные типы при успехе и ошибке
Функция, которая при успехе отдаёт список, а при ошибке строку, — ловушка: код дальше обратится к `[0]` и получит одну букву вместо фразы. Ошибка должна быть явной: исключение или результат с полем «успех / неуспех».
:::

:::mistake Брать только первую фразу
Сервис распознавания возвращает список фраз. `result[0]` теряет всё, что человек сказал после первой паузы. Склеивайте непустые фразы.
:::

:::mistake Верить распознанному тексту как написанному
«radio» вместо «Gradio» — обычное дело для названий и терминов. Модель получит текст с ошибками и ответит на него. В голосовых ботах переспрашивают, когда распознавание не уверено или текст пустой.
:::

## Что запомнить

- Звук в файле — отсчёты: частота дискретизации — сколько их в секунду, длительность = число отсчётов / частота.
- Громкость кадра — RMS отсчётов; по ней находят, где в записи речь, а где тишина.
- Голосовой бот — цепочка STT → языковая модель с историей → TTS; ошибки звеньев складываются.
- Ответ сервиса проверяют явно: статус, все фразы, пустой текст. Не берите `[0]` у того, что может оказаться строкой с ошибкой.
