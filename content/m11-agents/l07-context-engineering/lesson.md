## Зачем это нужно

С урока 11.3 мы всё время собираем то, что видит модель: инструкцию, найденные разделы, описания инструментов, историю шагов и результаты инструментов. На каждом шаге агента всё это отправляется заново: модель ничего не помнит между запросами (урок 10.3). У контекста три ограничения:

- **размер** — контекстное окно модели конечно;
- **цена** — оплачивается каждый токен каждого запроса;
- **внимание** — чем больше лишнего текста, тем труднее модели найти в нём нужное и тем легче отвлечься.

Промпт-инжиниринг (модуль 10) — о том, **как** сформулировать запрос. **Контекст-инженерия** — о том, **что** положить в контекст на каждом шаге, в каком порядке и как уложиться в бюджет. Слово стало популярным в 2025 году, когда агенты начали работать десятками шагов.

## Из чего складывается контекст агента

Соберём контекст нашего агента после нескольких шагов. Он трижды искал по урокам курса, и инструмент поиска каждый раз возвращал три найденных раздела целиком:

```python
system = ('Ты — помощник по курсу «Анализ данных и искусственный интеллект». Отвечай по-русски, коротко, '
          'по материалам уроков, со ссылками [номер урока]. Если не знаешь — скажи «Не знаю».')
tools = ('- search_course: поиск по урокам курса; вход — вопрос или ключевые слова\n'
         '- lesson_info: оглавление урока; вход — номер урока, например 10.2\n'
         '- calculate: калькулятор; вход — выражение из чисел, + - * / и скобок')
question = 'Чем кросс-валидация лучше одной проверки и сколько блоков брать?'
found = [[d for d in docs if d['lesson'] == lesson][:3] for lesson in ['6.8', '6.7', '5.3']]
observations = ['\n\n'.join(f"[{d['lesson']}] {d['section']}\n{d['text']}" for d in group) for group in found]
history = '\n'.join(f'Thought: ищу ещё\nAction: search_course\nAction Input: …\nObservation: {o}' for o in observations)

parts = {'инструкция': system, 'инструменты': tools, 'вопрос': question, 'история шагов': history}
for name, text in parts.items():
    print(f'{name:14} {len(text):6} символов ≈ {tokens(text):5} токенов')
print(f"{'всего':14} {sum(len(t) for t in parts.values()):6} символов ≈ {sum(tokens(t) for t in parts.values()):5} токенов")
```

Инструкция, инструменты и вопрос вместе — меньше сотни токенов. Почти всё остальное — результаты инструментов: три поиска по три раздела дали больше 800 токенов, в девять раз больше всего остального. Так бывает у агентов почти всегда: больше всего места занимают ответы инструментов. Поэтому с ними и работает контекст-инженерия в первую очередь.

## Каждый шаг — заново

Модель на шаге 5 получает и инструкцию, и все четыре прошлых шага. Посчитаем, сколько токенов уходит за весь разговор, если каждый шаг добавляет 300 токенов результата:

```python
first = tokens(system + tools + question)          # первый запрос
added = 300                                        # результат инструмента и мысль модели на каждом шаге
sent = 0
for step in range(1, 11):
    request = first + added * (step - 1)           # запрос шага: начало и все прошлые шаги
    sent += request
    if step in (1, 2, 5, 10):
        print(f'шаг {step:2}: запрос {request:5} токенов, отправлено за разговор {sent:6}')
print('уникального текста:', first + added * 9, 'токенов')
```

За десять шагов в разговоре накопилось меньше трёх тысяч токенов уникального текста. Но каждый шаг пересылает всё, что было раньше, поэтому отправлено больше 14 тысяч. Общий объём растёт как квадрат числа шагов. Каждый лишний токен в начале разговора оплачивается на всех следующих шагах. Сокращать результат выгоднее сразу, а не потом.

## Сократить и скрыть

Два простых приёма для результатов инструментов. Первый — **обрезать** длинный результат и честно написать, что он обрезан. Второй — **скрыть** старые результаты: последние модели ещё нужны, а то, что было пять шагов назад, обычно уже учтено в её рассуждениях.

```python
def shorten(text, limit=300):
    if len(text) <= limit:
        return text
    return text[:limit].rstrip() + f' … [сокращено, всего {len(text)} символов]'

def mask_old(observations, keep=1):
    hidden = [f'[результат скрыт: {len(o)} символов]' for o in observations[:-keep]]
    return hidden + observations[-keep:]

compact_obs = [shorten(o) for o in mask_old(observations)]      # старые скрыть, последний — обрезать
for o in compact_obs:
    print(o[:120], '…' if len(o) > 120 else '')
print('было:', sum(tokens(o) for o in observations), 'токенов, стало:', sum(tokens(o) for o in compact_obs))
```

Из 786 токенов осталось 78 — в десять раз меньше, и экономия повторится на каждом следующем шаге. Пометки «сокращено» и «скрыт» важны. Модель должна знать, что часть данных она не видит, — иначе примет обрезанный текст за полный. Если скрытое понадобится, агент вызовет инструмент ещё раз.

## Сжать историю в пересказ

Когда история приближается к пределу окна, её начало заменяют **пересказом**, а последние сообщения оставляют как есть. Пересказ пишет модель — отдельным запросом «перескажи, что уже сделано и что выяснили». Здесь, чтобы не звать модель, пересказ соберём программой из шагов:

```python
steps = [('search_course', 'кросс-валидация', 'нашлись разделы урока 6.8'),
         ('lesson_info', '6.8', 'урок «Кросс-валидация: несколько проверок вместо одной»'),
         ('search_course', 'сколько блоков', 'раздел «Сколько блоков» урока 6.8'),
         ('lesson_info', '6.7', 'урок о честном сравнении моделей')]

def compact(steps, keep_last=2):
    old, recent = steps[:-keep_last], steps[-keep_last:]
    summary = 'Пересказ: ' + '; '.join(f'{tool}({arg}) — {result}' for tool, arg, result in old)
    return [summary] + [f'{tool}({arg}) → {result}' for tool, arg, result in recent]

for line in compact(steps):
    print(line)
```

Сжатие теряет детали: в пересказе нет текста разделов, только итог. Поэтому то, что нельзя потерять, держат вне истории. Цель пользователя, ограничения и принятые решения записывают в правила и **заметки** — отдельный текст или файл. Агент перечитывает их на каждом шаге, и они никогда не сжимаются.

## Агент для программирования: OpenCode

В программе курса эта неделя называется «OpenCode + контекст-инженерия». **OpenCode** — открытый ИИ-агент для программирования, работает в терминале. Его инструменты читают файлы и ищут по ним, правят код, выполняют команды и читают веб-страницы. Контекст-инженерия в нём видна на каждом шагу. По документации OpenCode (ноябрь 2026 года):

- **правила проекта** лежат в файле `AGENTS.md` в корне проекта и действуют для этой папки и вложенных. Команда `/init` просматривает важные файлы репозитория, может задать пару уточняющих вопросов и создаёт или улучшает `AGENTS.md`. Общие правила для всех проектов лежат в `~/.config/opencode/AGENTS.md`. Если `AGENTS.md` нет, OpenCode читает `CLAUDE.md`;
- **два основных агента**: Build — работает по умолчанию, с полным набором инструментов, и Plan — изучает проект и составляет план, не меняя файлов проекта. Переключаются клавишей Tab;
- **права** на действия: `allow` — разрешено, `ask` — спросить человека, `deny` — запрещено. Это политика инструментов из урока 11.6;
- **сжатие сессии**: когда разговор приближается к пределу контекста модели, OpenCode пересказывает его целиком и оставляет рядом с пересказом самые свежие сообщения — по умолчанию около 15 000 токенов. Сжатие включено по умолчанию; в документации прямо сказано, что оно теряет детали;
- **MCP-серверы** подключаются в настройках, локальные и удалённые (урок 11.5).

Правила проекта — это контекст, который агент получает в начале каждой сессии. Пишут их коротко и только о том, чего агент не узнает из кода сам. Например:

```text
# Правила проекта
- Данные лежат в data/, результаты — в reports/. Папку private/ не открывать и не менять.
- Перед изменением кода запускай тесты: pytest -q. Сломал тест — сначала почини.
- Новые зависимости не ставить без вопроса.
- Комментарии и сообщения — по-русски, коротко.
```

Настройки и команды OpenCode меняются от версии к версии — проверяйте их по документации своей версии. Сами идеи — правила, заметки, права, сжатие — общие для агентов.

## Типичные ошибки

:::mistake Класть в контекст всё «на всякий случай»
Двадцать найденных разделов, полные ответы инструментов, вся история с начала — это дорого, медленно и отвлекает модель от нужного. Каждый кусок контекста должен быть нужен для текущего шага.
:::

:::mistake Сокращать молча
Обрезанный без пометки результат модель примет за полный и сделает неверный вывод. Пометка «сокращено, всего 1 840 символов» говорит, что данных больше и их можно запросить.
:::

:::mistake Сжимать главное
Цель пользователя, запреты и принятые решения в пересказе могут потеряться. Их хранят отдельно — в правилах и заметках, которые агент получает на каждом шаге без сжатия.
:::

## Что запомнить

- Контекст-инженерия решает, что модель видит на каждом шаге: инструкции, правила, инструменты, документы, историю и результаты.
- Больше всего места занимают результаты инструментов, а каждый шаг пересылает всё заново: общий объём растёт как квадрат числа шагов.
- Длинные результаты обрезают с пометкой, старые — скрывают, историю — сжимают в пересказ.
- То, что нельзя потерять (цель, запреты, решения), хранят в правилах и заметках вне сжимаемой истории.
- В агентах для программирования правила проекта лежат в файле вроде `AGENTS.md`, а длинная сессия сжимается автоматически.
