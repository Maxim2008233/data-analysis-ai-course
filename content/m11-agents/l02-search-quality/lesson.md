## Зачем это нужно

В уроке 11.1 мы смотрели на поиск глазами: на один запрос он ответил хорошо, на другой — мимо. Так нельзя ни сравнить два способа поиска, ни понять, стало ли лучше после изменения. Поиск проверяют как любую модель (урок 10.8): на наборе запросов с известными правильными ответами — и одним числом.

Для RAG это особенно важно. Модель видит только то, что нашёл поиск. Если нужного раздела нет в первых k результатах, никакой промпт не поможет: модель либо скажет «не знаю», либо выдумает.

## Проверочные запросы

У курса есть готовая разметка. Каждая статья справочника привязана к понятию, а понятие вводится в определённом уроке. Значит, на запрос «Утечка данных» поиск должен вернуть раздел урока 5.4.

```python
print('Запросов:', len(queries), '| уроков среди ответов:', len({q['lesson'] for q in queries}))
for q in queries[::40]:
    print(f"{q['term']:45} → урок {q['lesson']}")
```

Это строгая проверка: засчитывается только урок, где понятие **вводится**, хотя упоминаться оно может и в других. И мягкая одновременно: запросы — короткие названия терминов, почти дословно из текста уроков. Настоящие вопросы людей длиннее и сформулированы иначе, поэтому на них поиск ошибается чаще.

## recall@k

Для каждого запроса найдём **место** — на какой позиции выдачи стоит первый раздел нужного урока. **recall@k** — доля запросов, у которых это место не дальше k:

```python
def first_rank(scores, right):
    """Место (с 1) первого раздела нужного урока или None, если среди похожих разделов его нет."""
    for place, j in enumerate(np.argsort(-scores, kind='stable'), start=1):
        if scores[j] <= 0:
            return None
        if lessons[j] == right:
            return place
    return None

def evaluate(vectorizer):
    X = vectorizer.fit_transform(texts)
    S = (vectorizer.transform([q['term'] for q in queries]) @ X.T).toarray()   # запросы × разделы
    return [first_rank(S[i], q['lesson']) for i, q in enumerate(queries)]

def recall_at(ranks, k):
    return np.mean([r is not None and r <= k for r in ranks])

ranks_words = evaluate(TfidfVectorizer())
for k in [1, 3, 5, 10]:
    print(f'recall@{k:<2} = {recall_at(ranks_words, k):.1%}')
print('Не нашлось вовсе:', sum(r is None for r in ranks_words))
```

Нужный урок первым — в 76,9 % запросов, в первой пятёрке — в 93,2 %. Чем больше k, тем выше recall, но тем длиннее промпт: каждый найденный раздел — сотни токенов. Для RAG выбирают k, при котором recall уже высокий, а контекст ещё помещается в бюджет. Часто это 3–5.

## Где поиск промахивается

```python
misses = [(q['term'], q['lesson'], r) for q, r in zip(queries, ranks_words) if r is None or r > 5]
print(len(misses), 'промахов мимо пятёрки:')
for term, lesson, r in misses:
    print(f'  {term:45} урок {lesson}, место {r}')
```

Причины видны по списку. Чаще всего в нужном уроке те же слова стоят в других формах. «Кодирование категорий» не нашлось вовсе: в уроке 7.1 пишут «кодирования», «кодировать», «категории». У «Разбиения в дереве» в уроке 6.4 — «разбиения» и «дерева». В запросе «& | ~ (логические операции с масками)» символы векторизатор выбрасывает, а в уроке 1.5 — «логическая маска». Бывает и другое: «Нейронная сеть» вводится в уроке 0.1, а подробно о сетях рассказывает модуль 8, туда поиск и ведёт. Строгая разметка засчитывает только урок, где понятие появилось впервые.

## Символьные n-граммы

Формы слова различаются окончанием, а начало у них общее. Если резать текст не на слова, а на кусочки по 3–5 букв, у «переобучением» и «переобучение» большинство кусочков совпадёт:

```python
char = TfidfVectorizer(analyzer='char_wb', ngram_range=(3, 5))
analyzer = char.build_analyzer()
print(analyzer('переобучением')[:10])
a, b = set(analyzer('переобучением')), set(analyzer('переобучение'))
print(f'общих кусочков: {len(a & b)} из {len(a)} и {len(b)}')

ranks_char = evaluate(char)
for k in [1, 3, 5, 10]:
    print(f'recall@{k:<2}: слова {recall_at(ranks_words, k):.1%} → n-граммы {recall_at(ranks_char, k):.1%}')
```

`analyzer='char_wb'` берёт кусочки только внутри слов. Каждое слово дополняется пробелами, поэтому « пе» — начало слова, а «ием» — его конец. Из 36 кусочков «переобучением» 30 есть и у «переобучение». Словарь вырос с 9 тысяч слов до 79 тысяч кусочков, зато recall@5 поднялся с 93,2 % до 96,2 %, а «не нашлось вовсе» больше нет.

## Лучше — не везде

```python
better = [(q['term'], a, b) for q, a, b in zip(queries, ranks_words, ranks_char) if (a is None or a > 5) and b and b <= 5]
worse = [(q['term'], a, b) for q, a, b in zip(queries, ranks_words, ranks_char) if a and a <= 5 and (b is None or b > 5)]
print('Исправились:', len(better), better[:4])
print('Сломались:  ', len(worse), worse)
X_char = char.transform(texts)
for query in ['как бороться с переобучением', 'рецепт борща']:
    s = (X_char @ char.transform([query]).T).toarray().ravel()
    i = int(np.argmax(s))
    print(f'{query!r}: урок {lessons[i]}, «{docs[i]["section"]}», сходство {s[i]:.3f}')
```

Десять промахов исправились, три запроса сломались. «R² (коэффициент детерминации)» был на первом месте, а стал 27-м. Кусочки «коэф», «оэфф», «ффи» совпали со всеми разделами о коэффициентах регрессии, а редкое «R²» дало всего три коротких кусочка. Устойчивость к формам слова, которая помогла одним запросам, помешала другим. Запрос «как бороться с переобучением» теперь приводит в урок 5.3 — туда, куда нужно.

Но посмотрите на «рецепт борща». По словам у него было сходство 0 со всеми разделами. По кусочкам — уже 0,071 с разделом урока 10.7: у «рецепта» и «цепочки» общий кусочек «цеп». Правило «сходство 0 — не нашлось» с n-граммами не работает. Нужен порог, и подбирать его будем в уроке 11.3.

## Типичные ошибки

:::mistake Подбирать настройки и оценивать на одних запросах
Мы попробовали несколько вариантов поиска и выбрали лучший по тем же 234 запросам — такая оценка завышена, как ошибка модели на обучающей выборке. Настройки выбирают на одной части запросов, а итог сообщают по другой (задание со звёздочкой).
:::

:::mistake Смотреть только на recall@1
Для RAG в промпт попадает несколько разделов, и нужный урок на третьем месте модель тоже увидит. Смотрите recall при том k, которое реально пойдёт в контекст.
:::

:::mistake Верить одному числу без разбора ошибок
Средний recall вырос, а три запроса сломались. Список промахов показывает, где способ поиска слаб (короткие обозначения, символы, английские названия функций), и подсказывает следующий шаг.
:::

## Что запомнить

- Поиск проверяют на запросах с известным правильным документом, а не на паре удачных примеров.
- recall@k — доля запросов, у которых правильный документ среди первых k; для RAG важен recall при том k, что пойдёт в промпт.
- Символьные n-граммы (`analyzer='char_wb'`) устойчивы к формам слов: recall@5 вырос с 93,2 % до 96,2 %, но часть запросов стала хуже.
- С n-граммами у любого запроса сходство больше нуля — «не нашлось» определяют порогом.
- Настройки выбирают на одной части запросов, а итог оценивают на другой.
