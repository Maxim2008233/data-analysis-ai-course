## Зачем это нужно

RAG (Retrieval-Augmented Generation) отвечает на вопрос в три шага: найти документы → вставить их в промпт → попросить модель ответить по ним. Без первого шага ничего не выйдет: модель увидит только то, что нашёл поиск.

Наша база знаний — 729 разделов уроков курса. На вопрос «что такое температура языковой модели» поиск должен вернуть урок 10.2, а на «рецепт борща» — честно ничего.

Сегодня — простейший поиск, который работает: **TF-IDF**. Он из классического информационного поиска, считается за доли секунды и работает прямо в браузере. В промышленных системах часто ищут по эмбеддингам нейросети — такой поиск находит и синонимы. Но устроен он так же: тексты превращают в векторы и сравнивают косинусом.

## Мешок слов

Самый простой вектор текста — сколько раз в нём встречается каждое слово:

```python
mini = ['Модель учится на обучающей выборке.',
        'Переобученная модель запоминает шум обучающей выборки.',
        'Тестовая выборка нужна для честной оценки модели.']
cv = CountVectorizer()
counts = cv.fit_transform(mini)
print(cv.get_feature_names_out())
print(counts.toarray())
```

`CountVectorizer` переводит слова в нижний регистр, режет текст на слова из двух и больше букв или цифр и строит словарь. Строка матрицы — документ, столбец — слово из словаря. Порядок слов теряется, отсюда название «мешок слов».

Обратите внимание: «выборка», «выборке» и «выборки» — три разных столбца. Программа не знает, что это одно слово в разных падежах.

## TF-IDF: редкие слова важнее

Слова вроде «на» и «для» встречаются почти везде и ничего не говорят о теме. TF-IDF уменьшает их вес:

- **tf** — сколько раз слово встречается в документе;
- **idf** — насколько слово редкое во всей коллекции. В scikit-learn idf = ln((1 + n) / (1 + df)) + 1, где n — число документов, df — в скольких из них есть слово;
- вес слова — tf × idf, а вектор документа нормируют на длину 1.

```python
tfidf = TfidfVectorizer()
X_mini = tfidf.fit_transform(mini)
for word, idf in zip(tfidf.get_feature_names_out()[5:8], tfidf.idf_[5:8]):
    print(f'{word:10} idf = {idf:.3f}')
n = len(mini)
df = (counts.toarray() > 0).sum(axis=0)                    # в скольких документах есть слово
print('Формула совпала:', np.allclose(np.log((1 + n) / (1 + df)) + 1, tfidf.idf_))
print('Длины векторов:', np.linalg.norm(X_mini.toarray(), axis=1))
```

«модель» есть в двух документах из трёх, и её idf меньше, чем у «модели», которая встретилась один раз. Все векторы — длины 1. Значит, косинусное сходство двух документов — это просто скалярное произведение их векторов.

## Векторы всех разделов

```python
vectorizer = TfidfVectorizer()
X = vectorizer.fit_transform(texts)
print('Матрица:', X.shape, '| ненулевых в строке в среднем:', round(X.nnz / X.shape[0]))
words = vectorizer.get_feature_names_out()
common = np.argsort(vectorizer.idf_)[:8]
print('Самые частые слова:', [str(words[i]) for i in common])
```

В словаре 9167 слов, но в каждом разделе в среднем всего 66 из них. Остальные клетки строки — нули. Поэтому `X` хранится как **разреженная матрица**: в памяти лежат только ненулевые числа, а `.toarray()` превращает её в обычную. Самые частые слова — «не», «по», «на», «для», «это» — получили наименьший idf, как и задумано.

## Поиск: запрос → k разделов

Запрос переводят в вектор **тем же** векторизатором: `transform`, а не `fit` — словарь и idf берутся от документов. Векторы документов уже длины 1, поэтому сходство со всеми разделами сразу — одно умножение `X @ q.T`:

```python
def search(query, k=3):
    q = vectorizer.transform([query])
    scores = (X @ q.T).toarray().ravel()                  # косинусы со всеми 729 разделами
    top = np.argsort(-scores, kind='stable')[:k]
    return [(docs[i]['lesson'], docs[i]['section'], round(float(scores[i]), 3)) for i in top]

for query in ['что такое температура языковой модели', 'почему нельзя хранить ключ в коде', 'рецепт борща']:
    print(query)
    for hit in search(query):
        print('   ', hit)
```

Первые два запроса нашли нужные уроки — 10.2 «Температура» и 10.1 «Ключ — не в коде». У «рецепта борща» сходство со всеми разделами 0: ни одного общего слова. Поиск всё равно вернул три раздела — первые по порядку. Отличить «нашлось» от «ничего не нашлось» должна программа, по порогу сходства. Займёмся этим в уроке 11.3.

## Когда слова не совпадают

```python
for hit in search('как бороться с переобучением'):
    print(hit)
analyzer = vectorizer.build_analyzer()                     # как векторизатор режет текст на слова
for w in analyzer('как бороться с переобучением'):
    print(f'{w:15} в словаре: {w in vectorizer.vocabulary_}')
print([str(w) for w in words if w.startswith('переобуч')])
```

Первым нашёлся раздел про `loc` и `iloc` — мимо. Слово «с» короче двух букв и выброшено. «Бороться» в курсе не встречается, «переобучением» — тоже: в уроках есть другие формы этого слова. От запроса осталось одно «как», и первым оказался короткий раздел, где «как» повторяется трижды. А «переобучение», «переобучения», «переобучена» в словаре есть, только для векторизатора это разные слова.

В уроке 11.2 разберёмся, как измерить качество поиска и как сделать его устойчивым к формам слов.

## Типичные ошибки

:::mistake fit на запросе
`TfidfVectorizer().fit_transform([query])` строит новый словарь — из слов запроса. Такой вектор нельзя сравнивать с векторами документов: у них другие столбцы. Векторизатор обучают (`fit`) один раз на документах, а запросы только переводят (`transform`).
:::

:::mistake Сходство 0 — тоже «результат»
`argsort` всегда вернёт k номеров, даже если ни один раздел не похож на запрос. Проверяйте само сходство: при нуле или близком к нулю честнее ответить «не нашлось».
:::

:::mistake Ждать от TF-IDF понимания смысла
TF-IDF сравнивает слова, а не смысл. Синонимы («нейросеть» и «нейронная сеть») и другие формы слова для него — разные слова. Смысл ближе к эмбеддингам нейросетей, а формы слов спасают символьные n-граммы (урок 11.2).
:::

## Мини-квиз

```quiz
- q: У слова маленький idf. Что это значит?
  options:
    - Слово встречается во многих документах и мало говорит о теме
    - Слово редкое и важное
    - Слово встречается в документе много раз
  answer: 0
  explain: idf — мера редкости слова во всей коллекции. Частые везде слова («не», «на», «для») получают наименьший idf.
- q: Как получить вектор запроса для поиска?
  options:
    - vectorizer.transform([query]) тем же векторизатором, что обучен на документах
    - TfidfVectorizer().fit_transform([query])
    - vectorizer.fit([query]) и затем transform
  answer: 0
  explain: Словарь и idf должны быть от документов, иначе столбцы векторов не совпадут. fit на запросе переучит векторизатор.
- q: Почему сходство с документами можно считать как X @ q.T без деления на длины?
  options:
    - TfidfVectorizer нормирует каждый вектор на длину 1
    - Потому что матрица разреженная
    - Деление на длины не нужно никогда
  answer: 0
  explain: Для векторов длины 1 косинус равен скалярному произведению.
```

## Что запомнить

- TF-IDF — вектор документа: tf (сколько раз слово в документе) × idf (насколько оно редкое в коллекции), нормированный на длину 1.
- Векторизатор обучают на документах (`fit_transform`), запросы только переводят (`transform`).
- Поиск — косинусы запроса со всеми документами (`X @ q.T`) и k лучших по убыванию.
- Поиск возвращает k результатов всегда — нулевое сходство значит «не нашлось».
- TF-IDF не знает ни синонимов, ни форм слов: «переобучением» и «переобучение» для него разные слова.
