## Зачем это нужно

Языковая модель не читала наш курс, и о нём она ответит общими словами или выдумает. Переобучать модель ради каждого нового документа долго и дорого. **RAG** (Retrieval-Augmented Generation, генерация с дополненной выборкой) поступает проще (лекция, слайд 9):

1. **Retrieve** — найти документы, похожие на вопрос;
2. **Augment** — вставить их в промпт;
3. **Generate** — попросить модель ответить только по ним, со ссылками на источник.

Что это даёт:

- модель отвечает по свежим и закрытым документам, которых не было в её обучении;
- ответ можно проверить: видно, на какой урок он опирается;
- выдумок меньше — но не ноль, поэтому ссылки проверяет программа.

## Поиск с порогом

Ищем символьными n-граммами (урок 11.2). Первым делом — решить, нашлось ли вообще что-то. У «рецепта борща» сходство с лучшим разделом 0,071, а не ноль, поэтому нужен порог.

Порог подбираем на размеченных вопросах из файла `assistant_questions.json`. В нём 30 вопросов по курсу и 30 не по курсу, разделённых на две половины. На `dev` выбираем, на `test` проверяем — как в уроке 11.2.

```python
def search(question, k=3):
    scores = (X @ vectorizer.transform([question]).T).toarray().ravel()
    top = np.argsort(-scores, kind='stable')[:k]
    return [(float(scores[i]), docs[i]) for i in top]

dev = [q for q in questions if q['part'] == 'dev']
best = np.array([search(q['question'], 1)[0][0] for q in dev])     # сходство с лучшим разделом
about = np.array([q['about_course'] for q in dev])
print('по курсу: от', best[about].min().round(3), '| не по курсу: до', best[~about].max().round(3))
for t in [0.10, 0.15, 0.20, 0.25]:
    answer = best >= t
    print(f'порог {t:.2f}: верных решений {np.mean(answer == about):.0%}, '
          f'«не знаю» на вопросах по курсу {np.sum(~answer & about)}, ответов не по теме {np.sum(answer & ~about)}')
```

Низкий порог пропускает вопросы не по теме: модель будет отвечать про велосипеды, глядя в разделы про машины. Высокий порог — «не знаю» на законные вопросы. На `dev` порог 0,20 разделяет вопросы без ошибок, но зазор крошечный: самый похожий на курс «чужой» вопрос («Как правильно бегать по утрам?») набрал 0,193, а самый далёкий вопрос по курсу — 0,202. Сколько ошибок даст этот порог на новых вопросах, проверим в задании.

## Промпт с контекстом

Найденные разделы вставляем в промпт. У каждого — номер урока в квадратных скобках, чтобы модели было на что ссылаться:

```python
SYSTEM = ('Ты — помощник по курсу «Анализ данных и искусственный интеллект». Отвечай только по разделам уроков '
          'из контекста. После каждого утверждения ставь номер урока в квадратных скобках, например [10.2]. '
          'Если в контексте нет ответа, ответь: «Не знаю».')

def build_messages(question, hits):
    blocks = [f"[{d['lesson']}] {d['lesson_title']} — {d['section']}\n{d['text']}" for score, d in hits]
    context = '\n\n'.join(blocks)
    return [SystemMessage(SYSTEM), HumanMessage(f'Контекст:\n{context}\n\nВопрос: {question}')]

question = 'Что такое температура языковой модели?'
hits = search(question)
messages = build_messages(question, hits)
print(messages[1].content[:600], '…')
n_chars = sum(len(m.content) for m in messages)
print(f'\nСимволов в промпте: {n_chars} ≈ {n_chars / 5.09:.0f} токенов')
```

Три раздела вместе с инструкцией — около 1800 символов, по оценке из урока 10.3 это примерно 350 токенов GigaChat. Каждый лишний раздел делает запрос дороже, а ещё размывает внимание модели. Поэтому k берут небольшим — таким, при котором recall уже высокий (урок 11.2).

Инструкция делает три вещи: ограничивает источник («только по контексту»), задаёт формат ссылок и разрешает честный отказ. Без последнего пункта модель будет стараться ответить любой ценой.

## Ответ и проверка ссылок

Настоящему GigaChat нужен ключ, поэтому здесь отвечает тестовая модель (урок 10.7). Её ответ мы написали сами — специально с одной ошибкой, которую делают и настоящие модели:

```python
model = FakeListChatModel(responses=[
    'Температура меняет вероятности следующего токена: при низкой модель почти всегда выбирает самый вероятный '
    'токен, при высокой ответы разнообразнее, но чаще бессвязны [10.2]. Как модель считает эти вероятности, '
    'рассказано в уроке [9.1].'])
answer = model.invoke(messages).content
cited = re.findall(r'\[(\d+\.\d+)\]', answer)
allowed = {d['lesson'] for score, d in hits}
print('В контексте уроки:', sorted(allowed))
print('Ссылки в ответе:', cited)
print('Ссылки не из контекста:', [c for c in cited if c not in allowed])
```

Модели дали только разделы урока 10.2, а она сослалась ещё и на 9.1. Возможно, урок 9.1 действительно об этом — но этого текста модель не видела, и ссылка взята «из головы». Такие уверенные выдумки называют **галлюцинациями**. Программа ловит их простой проверкой: каждая ссылка должна вести на раздел из контекста.

В Colab вместо тестовой модели подставляют настоящую: `model = GigaChat(credentials=ключ, verify_ssl_certs=False)` из `langchain_gigachat`. Код вокруг не меняется.

## RAG целиком

```python
def rag_answer(question, model, threshold=0.20, k=3):
    hits = search(question, k)
    if hits[0][0] < threshold:                               # похожих разделов нет — модель не зовём
        return 'Не знаю: в уроках курса об этом нет.'
    answer = model.invoke(build_messages(question, hits)).content
    allowed = {d['lesson'] for score, d in hits}
    bad = [c for c in re.findall(r'\[(\d+\.\d+)\]', answer) if c not in allowed]
    if bad:
        answer += f'\n(Ссылки {bad} не из найденных разделов — проверьте их.)'
    return answer

model = FakeListChatModel(responses=['Кросс-валидация делит данные на k блоков и по очереди проверяет модель на каждом [6.8].'])
print(rag_answer('Рецепт борща', model))
print('Вызовов модели:', len(model.calls))
print(rag_answer('Что такое кросс-валидация?', model))
print('Вызовов модели:', len(model.calls))
```

На вопрос о борще модель не вызывалась: порог отсёк его до запроса. Это и дешевле, и честнее. Модель с инструкцией «отвечай по контексту» на чужие разделы всё равно может что-то сочинить. На вопрос о кросс-валидации поиск нашёл урок 6.8, и ссылка в ответе прошла проверку.

## Типичные ошибки

:::mistake Думать, что RAG убирает выдумки
Модель может проигнорировать контекст, смешать его со своими знаниями или сослаться на урок, которого не видела. Инструкция снижает риск, проверка ссылок ловит часть ошибок, но ответ всё равно стоит читать критически.
:::

:::mistake Звать модель, когда ничего не нашлось
Поиск всегда возвращает k разделов — даже на «рецепт борща». Без порога модель получит случайные разделы и либо скажет «не знаю», либо выдумает ответ по ним. Решение «отвечать или нет» принимает программа — до запроса.
:::

:::mistake Класть в контекст всё подряд
Двадцать разделов вместо трёх — это дороже, медленнее, и нужный раздел теряется среди лишних. Размер контекста выбирают по recall@k и бюджету токенов.
:::

## Что запомнить

- RAG: найти разделы → вставить их в промпт → попросить модель отвечать только по ним, со ссылками.
- Решение «отвечать или «не знаю»» принимает программа по порогу сходства — до вызова модели.
- Порог и k выбирают на одной части размеченных вопросов, а проверяют на другой.
- Инструкция в промпте ограничивает источник, задаёт формат ссылок и разрешает честный отказ.
- Ссылки в ответе проверяют программой: каждая должна вести на раздел из контекста. Иначе это галлюцинация.
