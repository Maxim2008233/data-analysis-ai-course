## Зачем это нужно

Год выпуска — не единственное, что влияет на цену: пробег, объём двигателя, пробег в год тоже что-то говорят. Возьмём все четыре признака. Но они измеряются в разных единицах: годы (около 2 000), километры (сотни тысяч), кубические сантиметры (тысячи). Для многих методов это проблема: расстояния между машинами, штрафы за большие коэффициенты (модуль 7), шаги градиентного спуска (урок 5.2) зависят от масштаба. Поэтому признаки часто **стандартизируют** — приводят к одному масштабу. Делать это нужно так, чтобы не допустить утечки.

## StandardScaler

`StandardScaler` делает с каждым признаком то же, что мы делали вручную в уроке 1.10:

$$
z = \frac{x - \mu_{\text{train}}}{\sigma_{\text{train}}},
$$

где $\mu_{\text{train}}$ и $\sigma_{\text{train}}$ — среднее и стандартное отклонение признака **на обучающей части**. После этого у признака на train среднее 0 и σ = 1. Стандартизация не делает распределение нормальным и не загоняет значения в [0, 1]: z может быть отрицательным и больше 1.

Scaler тоже «обучается» — ему нужно узнать $\mu$ и $\sigma$. Ответы `y` ему не нужны:

```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
scaler.fit(X_train)                       # только обучающая часть!
print(pd.DataFrame({'среднее train (mean_)': scaler.mean_, 'σ train (scale_)': scaler.scale_}, index=features).round(1))
```

## transform для всех частей

Одним и тем же обученным scaler преобразуем и обучающую, и валидационную часть. Повторный `fit` на validation не делаем:

```python
X_train_s = scaler.transform(X_train)
X_valid_s = scaler.transform(X_valid)
print('Средние на train:', X_train_s.mean(axis=0).round(3))
print('Средние на validation:', X_valid_s.mean(axis=0).round(3))
print('Тип результата:', type(X_train_s).__name__, X_train_s.shape)
```

На train средние ровно 0, на validation — близкие к нулю, но не нулевые: это честно, ведь μ и σ взяты из train. `transform` возвращает массив NumPy без имён колонок. Короткая запись `scaler.fit_transform(X_train)` = `fit`, затем `transform` — только для train.

:::warning Почему не fit на всех данных
Если посчитать μ и σ по всей таблице, в подготовку модели попадут сведения о валидационных и тестовых машинах — утечка (урок 5.4). Здесь разница крошечная, но правило важнее: всё, что «учится», учится только на train.
:::

## Модель по четырём признакам

```python
model = LinearRegression()
model.fit(X_train_s, y_train)
pred_train = model.predict(X_train_s)
pred_valid = model.predict(X_valid_s)
print('Коэффициенты (на одно σ признака):', dict(zip(features, model.coef_.round(0))))
print(f'MAE train: {mean_absolute_error(y_train, pred_train):.0f}')
print(f'MAE validation: {mean_absolute_error(y_valid, pred_valid):.0f}')
```

- коэффициентов четыре — по одному на признак — плюс свободный член; прогноз по-прежнему в евро (`y` мы не масштабировали);
- ошибки на train и validation почти равны: переобучения нет — у модели всего 5 параметров на 19 тысяч машин;
- MAE ≈ 4 270 — лучше модели по одному году (≈ 5 100), но всё ещё хуже простой «медианы года» (≈ 4 040)! Линейная форма зависимости — главное ограничение.

На стандартизированных признаках коэффициенты сравнимы: каждый показывает изменение прогноза при изменении признака на **одно стандартное отклонение**. Год и объём двигателя повышают прогноз сильнее всего, пробег — понижает.

## Масштаб не меняет прогнозы линейной регрессии

Обучим ту же модель на исходных признаках:

```python
raw_model = LinearRegression().fit(X_train, y_train)
same = np.allclose(raw_model.predict(X_valid), pred_valid)
print('Прогнозы совпадают:', same)
print('Коэффициенты на исходных единицах:', dict(zip(features, raw_model.coef_.round(3))))
```

Прогнозы те же: линейная регрессия просто подбирает коэффициенты под единицы признаков. Меняется только их смысл: на исходных данных коэффициент при пробеге — «евро на километр», при годе — «евро на год», и сравнивать их по величине нельзя. Для линейной регрессии стандартизация — удобство и хорошая привычка; для ближайших соседей (модуль 6) и регуляризации (модуль 7) — необходимость.

## Типичные ошибки

:::mistake fit scaler на всех данных
μ и σ, посчитанные с участием validation и test, — утечка. `fit` — только на train.
:::

:::mistake Отдельный scaler для validation
Если обучить второй scaler на validation, части окажутся в разных «системах координат»: одинаковые машины получат разные z. Один scaler — `fit` на train, `transform` для всех.
:::

:::mistake Сравнивать коэффициенты на исходных единицах
«Коэффициент при пробеге −0,02 — значит, пробег не важен» — неверно: это евро на **километр**. Сравнивают коэффициенты на стандартизированных признаках.
:::

:::mistake Ждать нормального распределения
Стандартизация сдвигает и растягивает признак, форма распределения не меняется: длинный хвост остаётся хвостом.
:::

## Что запомнить

- `StandardScaler`: z = (x − μ_train) / σ_train; `scaler.fit(X_train)`, затем `transform` для train, validation и test; `fit` на всех данных — утечка.
- Результат `transform` — массив NumPy; `fit_transform` — только для обучающей части.
- На стандартизированных признаках коэффициенты сравнимы: изменение прогноза на одно σ признака.
- Масштаб не меняет прогнозы линейной регрессии, но важен для kNN, регуляризации и градиентного спуска.
