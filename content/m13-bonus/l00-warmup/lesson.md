## Зачем это нужно

В модулях 5–7 модели предсказывали число — цену машины. В бонус-модуле они будут отвечать классом: автомат или механика (уроки Б.1–Б.2), гибрид или нет (урок Б.3). В уроках Б.4–Б.5 ответов не будет совсем — будем искать устройство данных и группы похожих машин. А в уроке Б.6 напишем алгоритмы сами.

Почти все инструменты для этого уже есть. Повторим их на машинах курса — с теми же тремя частями данных, что в модулях 5–6.

## Метка класса и доли по группам

В **бинарной классификации** (урок 8.7) ответ — 0 или 1. Здесь 1 — автомат (`AutoTransmission`), 0 — механика. Модель даёт вероятность класса 1, а класс выбирают по порогу, обычно 0,5. Среднее метки — доля класса 1, а `groupby` (урок 3.2) считает эту долю в каждой группе:

```python
print('доля автоматов:', round(y.mean(), 3))
cars.groupby('Fuel_type')['AutoTransmission'].agg(['size', 'mean']).sort_values('mean', ascending=False).round(3)
```

Автоматов 45,5 %. У гибридов почти все — автоматы (99 %), у машин на метане и пропане — 36 %. Вид топлива подсказывает класс, но не решает его: у бензиновых и дизельных машин автоматов около 42 %.

## Честная проверка и ориентир

Данные разбиты на три части, как в модулях 5–6 (урок 5.4): 19 239 машин для обучения и по 6 414 — для валидации и теста. Модель учат на обучающей части, выбирают по валидационной, а тест открывают один раз в конце (урок 5.3). **Утечка** (урок 5.4) — когда при обучении используется то, чего не будет при настоящем применении, например ответы проверочной части.

**Ориентир** (урок 5.5) для классификации — «всегда самый частый класс»:

```python
from sklearn.dummy import DummyClassifier

dummy = DummyClassifier(strategy='most_frequent').fit(X_train, y_train)
print('ориентир «всегда механика» на валидации:', round(dummy.score(X_valid, y_valid), 3))
```

У классификатора `score` — доля верных ответов. Ориентир верен в 54,8 % случаев: механик чуть больше половины. Модель коробки передач полезна, только если заметно обгоняет это число.

## Масштаб и конвейер

Признаки в разных единицах — годы, километры, кубические сантиметры, евро — стандартизуют (урок 5.7). `StandardScaler` вычитает среднее и делит на стандартное отклонение, причём запоминает их **по обучающей части**, а к остальным частям только применяет. Категориальные признаки превращают в столбцы из нулей и единиц — **One-Hot** (урок 7.4). Разные преобразования для разных столбцов собирает `make_column_transformer` (урок 7.2). Всё вместе с моделью — один конвейер (урок 6.1): `fit` обучает все шаги по обучающей части, `predict` применяет их к новым данным.

```python
from sklearn.compose import make_column_transformer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.pipeline import make_pipeline
from sklearn.linear_model import LinearRegression

cars_train = cars.loc[X_train.index]                  # те же машины, что в X_train, со всеми столбцами
prep = make_column_transformer((StandardScaler(), ['Year', 'Distance', 'Engine']),
                               (OneHotEncoder(handle_unknown='ignore'), ['Fuel_type']))
price_model = make_pipeline(prep, LinearRegression()).fit(cars_train, cars_train['Price'])
print('столбцов после подготовки:', price_model[0].transform(cars_train.head(1)).shape[1])
```

Три числовых столбца плюс шесть видов топлива — девять столбцов. Остальные столбцы таблицы `make_column_transformer` отбрасывает. В бонусе вместо `LinearRegression` в конце конвейера будет стоять классификатор.

## Градиентный спуск

Модели учатся, уменьшая потери шагами против градиента (урок 5.2): w ← w − lr · градиент. Многое решает размер шага `lr`. Найдём минимум функции (w − 3)², её градиент — 2 · (w − 3):

```python
for lr in (0.01, 0.1, 1.1):
    w = 0.0
    for step in range(30):
        w -= lr * 2 * (w - 3)
    print(f'lr = {lr}: через 30 шагов w = {w:.3f}')
```

С `lr = 0.1` за 30 шагов спуск почти пришёл к минимуму w = 3. С `lr = 0.01` прошёл меньше половины пути, а с `lr = 1.1` каждый шаг перепрыгивает минимум всё дальше, и спуск расходится. В уроке Б.1 так же будем уменьшать log loss логистической регрессии.

## Дерево: вопрос «признак ≤ порог»

Дерево решений (урок 6.4) задаёт вопросы вида «признак ≤ порог». В модуле 6 листья отвечали средней ценой, а у классификатора `DecisionTreeClassifier` лист отвечает самым частым классом своих машин. Порог дерево выбирает так, чтобы в частях классы были как можно чище. Как именно меряют чистоту, разберём в уроке Б.6.

```python
from sklearn.tree import DecisionTreeClassifier, export_text

tree = DecisionTreeClassifier(max_depth=2, random_state=0).fit(X_train, y_train)
print(export_text(tree, feature_names=list(X.columns), decimals=1))
print(f'глубина 2 — доля верных на валидации: {tree.score(X_valid, y_valid):.3f}')
deep = DecisionTreeClassifier(random_state=0).fit(X_train, y_train)
print(f'без ограничения глубины: обучение {deep.score(X_train, y_train):.3f}, валидация {deep.score(X_valid, y_valid):.3f}')
```

Первый вопрос — о цене, второй — об объёме двигателя. Уже два вопроса дают 79,9 % верных против 54,8 % у ориентира. Дерево без ограничения глубины запоминает обучающие машины (99,9 % верных), а на валидации ошибается чаще дерева глубины 2: это переобучение (уроки 5.3 и 6.5).
