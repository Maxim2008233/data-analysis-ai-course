## Зачем это нужно

Представим сайт объявлений. Продавцы часто не указывают коробку передач, и сайт хочет сам ставить метку «автомат» по году, пробегу, двигателю и цене — модель из урока Б.1. Ошибки здесь двух видов, и стоят они по-разному:

- **пропуск** — автомат без метки: покупатель с фильтром «автомат» эту машину не найдёт;
- **ложное срабатывание** — механика с меткой: покупатель приедет и уйдёт ни с чем.

Доля верных ответов складывает обе ошибки в одно число и не говорит, каких больше. Сегодня разложим ошибки по видам, посмотрим на все пороги сразу и выберем порог под задачу. Данные разбиты на три части, как в модуле 5: на обучающей модель учится, на валидационной выбираем порог, на тестовой проверяем один раз.

## Матрица ошибок

```python
pred = (p_test >= 0.5).astype(int)
cm = confusion_matrix(y_test, pred)
print(cm)
tn, fp, fn, tp = cm.ravel()
print(f'верно отказали (TN) {tn}, ложные срабатывания (FP) {fp}, пропуски (FN) {fn}, верно нашли (TP) {tp}')
print(f'доля верных: {(tp + tn) / cm.sum():.3f}')
```

**Матрица ошибок** — таблица 2 × 2. В scikit-learn строки — настоящий класс, столбцы — предсказанный, поэтому в первой строке механики, во второй автоматы. На диагонали верные ответы, вне её — ошибки. `ravel()` разворачивает таблицу в четыре числа в порядке TN, FP, FN, TP. Пропусков (774) почти вдвое больше, чем ложных срабатываний (430). Доля верных 0,812 этого не показывала.

## Точность, полнота и F1

```python
precision = tp / (tp + fp)          # из названных автоматом — сколько правда автоматы
recall = tp / (tp + fn)             # из всех автоматов — сколько названо
f1 = 2 * precision * recall / (precision + recall)
print(f'точность {precision:.3f}, полнота {recall:.3f}, F1 {f1:.3f}')
print('то же в sklearn:', round(precision_score(y_test, pred), 3), round(recall_score(y_test, pred), 3), round(f1_score(y_test, pred), 3))
```

- **Точность** (precision) — доля верных среди найденных. 83 % машин с меткой «автомат» правда автоматы.
- **Полнота** (recall) — доля найденных среди настоящих. Метку получили 73,5 % автоматов, остальные покупатель с фильтром не увидит.
- **F1** — среднее гармоническое точности и полноты. Оно мало, если мала хотя бы одна из них: модель «назови автоматом всё» даёт полноту 1, но точность 0,455 и F1 0,63.

Мы уже встречали эти слова у детектора объектов в уроке 12.2 — там найденные рамки сравнивались с настоящими.

## Порог меняет одно на другое

```python
ths = np.linspace(0.05, 0.95, 19)
prec = [precision_score(y_valid, (p_valid >= t).astype(int)) for t in ths]
rec = [recall_score(y_valid, (p_valid >= t).astype(int)) for t in ths]
plt.figure(figsize=(6, 3))
plt.plot(ths, prec, label='точность')
plt.plot(ths, rec, label='полнота')
plt.xlabel('порог')
plt.legend()
plt.title('Валидация: точность и полнота при разных порогах')
plt.show()
```

Чем выше порог, тем реже модель ставит метку. Ставит она её только уверенно, поэтому точность растёт, а полнота падает. Одного «лучшего» порога нет: он зависит от того, какая ошибка дороже.

## ROC-кривая и AUC

Можно посмотреть на все пороги сразу. **ROC-кривая** для каждого порога откладывает долю найденных автоматов (TPR, это полнота) против доли механик, ошибочно названных автоматом (FPR):

```python
fpr, tpr, thresholds = roc_curve(y_test, p_test)
auc = roc_auc_score(y_test, p_test)
plt.figure(figsize=(4.5, 4.5))
plt.plot(fpr, tpr, label=f'логистическая регрессия, AUC = {auc:.3f}')
plt.plot([0, 1], [0, 1], ls='--', c='gray', label='угадывание, AUC = 0,5')
plt.xlabel('доля ложных срабатываний (FPR)')
plt.ylabel('доля найденных (TPR)')
plt.legend(loc='lower right')
plt.show()
```

Кривая идёт от точки (0, 0) — порог выше всех оценок, никого не называем, — до (1, 1), где называем всех. Чем ближе она к левому верхнему углу, тем лучше. **AUC** — площадь под кривой. У этой модели она 0,879, у угадывания — 0,5, у идеальной модели — 1.

У AUC есть простой смысл: это вероятность того, что случайный автомат получит оценку выше случайной механики. Проверим на случайных парах:

```python
rng = np.random.default_rng(0)
yt = y_test.to_numpy()
autos = rng.choice(p_test[yt == 1], 100_000)
manuals = rng.choice(p_test[yt == 0], 100_000)
print(f'в {np.mean(autos > manuals):.1%} случайных пар автомат оценён выше механики; AUC = {auc:.4f}')
```

AUC меряет, насколько хорошо модель **упорядочивает** машины, и не зависит от порога. Поэтому модели сравнивают по AUC, а порог выбирают потом, под задачу.

## Порог под задачу

Сайт решил: пропуски хуже, и метку должны получить хотя бы 90 % автоматов. Ищем на валидации самый высокий порог, при котором полнота не меньше 0,9, и проверяем его на тесте:

```python
ok = [t for t, r in zip(ths, rec) if r >= 0.9]
t90 = max(ok)
pred90 = (p_test >= t90).astype(int)
print(f'порог {t90:.2f}: полнота на тесте {recall_score(y_test, pred90):.3f}, точность {precision_score(y_test, pred90):.3f}, метку получат {pred90.mean():.0%} машин')
```

Порог 0,2 даёт на тесте полноту 0,923 — обещанные 90 % выполнены. Цена — точность 0,615: почти каждая третья метка ложная, а метку получают 68 % машин при 45 % настоящих автоматов. Выдержит ли сайт столько ложных меток, решают люди. Это решение принимают по этим числам, а не по доле верных.

## Типичные ошибки

:::mistake Выбирать порог по тестовой части
Порог — такой же гиперпараметр, как глубина дерева. Если подобрать его по тесту, оценка на тесте станет оптимистичной. Выбирайте на валидации, тест открывайте один раз.
:::

:::mistake Путать точность и долю верных
По-русски «точность» часто говорят про долю верных ответов. В метриках классификации точность (precision) — это доля верных среди найденных. Чтобы не путаться, в курсе accuracy называется «доля верных».
:::

:::mistake Читать строки и столбцы матрицы наоборот
В scikit-learn строки — настоящий класс, столбцы — предсказанный: `[[TN, FP], [FN, TP]]`. В учебниках встречается и обратный порядок, поэтому подписывайте числа.
:::

## Что запомнить

- Матрица ошибок: `[[TN, FP], [FN, TP]]` — верные отказы, ложные срабатывания, пропуски, верные находки.
- Точность — доля верных среди найденных, полнота — доля найденных среди настоящих, F1 — их среднее гармоническое.
- Порог меняет точность на полноту; его выбирают на валидации под цену ошибок.
- ROC-кривая показывает все пороги сразу; AUC — вероятность того, что случайный объект класса 1 оценён выше случайного объекта класса 0. От порога AUC не зависит.
