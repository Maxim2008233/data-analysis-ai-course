## Зачем это нужно

Национальная стратегия развития искусственного интеллекта до 2030 года называет ИИ комплексом технологий, который имитирует когнитивные функции человека. На конкретных задачах он даёт результаты, сопоставимые с человеческими (лекция, слайд 2). Стратегия выделяет пять технологий (слайд 3):

| Технология | Данные | Где в курсе |
|---|---|---|
| компьютерное зрение | картинки, видео | уроки 12.1–12.2, CLIP в модуле 9 |
| обработка естественного языка | тексты | уроки 12.3–12.4, модули 9–11 |
| распознавание и синтез речи | звук | урок 12.5, голосовой бот 11.8 |
| интеллектуальная поддержка принятия решений | таблицы, показания датчиков | модели модулей 5–8 |
| перспективные методы ИИ | любые | например, агенты из модуля 11 |

Технологию выбирают не по моде, а по данным задачи. Есть фотографии полок магазина — это зрение, есть журнал показаний датчиков — это табличная модель. Но модель, которая хорошо работает в среднем, ещё может навредить. Её ошибки стоят по-разному, достаются разным людям в разной мере, а данные для неё бывают личными. Это вторая половина урока.

## Цена ошибок: порог по стоимости

Представим систему, похожую на видеоаналитику Уралхима. По видео она оценивает уверенность, что оператор отвлёкся. Данные сгенерированы программой: 2000 эпизодов, оператор отвлекается в 5 % из них. Пропуск — оператор отвлёкся, а тревоги нет — грозит аварией и стоит 50 условных единиц. Ложная тревога — оператора зря побеспокоили — стоит 1.

```python
rng = np.random.default_rng(7)
n = 2000
distracted = (rng.random(n) < 0.05).astype(int)                 # 1 — оператор отвлёкся
score = np.clip(np.where(distracted == 1, rng.normal(0.65, 0.15, n), rng.normal(0.35, 0.15, n)), 0, 1)

ths = np.round(np.arange(0.05, 0.96, 0.01), 2)
acc = np.array([((score >= th) == distracted).mean() for th in ths])
misses = np.array([((score < th) & (distracted == 1)).sum() for th in ths])
alarms = np.array([((score >= th) & (distracted == 0)).sum() for th in ths])
cost = 50 * misses + 1 * alarms
ia, ic = acc.argmax(), cost.argmin()
print(f'оператор отвлекался в {distracted.sum()} эпизодах из {n}')
print(f'порог {ths[ia]} (лучший по доле верных): доля верных {acc[ia]:.3f}, пропусков {misses[ia]}, тревог зря {alarms[ia]}, стоимость {cost[ia]}')
print(f'порог {ths[ic]} (лучший по стоимости): доля верных {acc[ic]:.3f}, пропусков {misses[ic]}, тревог зря {alarms[ic]}, стоимость {cost[ic]}')
print(f'никогда не тревожить: доля верных {1 - distracted.mean():.3f}, стоимость {50 * distracted.sum()}')

fig, ax = plt.subplots(1, 2, figsize=(9, 3))
ax[0].plot(ths, acc)
ax[0].axvline(ths[ia], ls='--', c='gray')
ax[0].set_title('Доля верных')
ax[1].plot(ths, cost)
ax[1].axvline(ths[ic], ls='--', c='gray')
ax[1].set_title('Стоимость ошибок')
for a in ax:
    a.set_xlabel('порог')
plt.tight_layout()
plt.show()
```

Порог, лучший по доле верных, — 0,71: 96,7 % ответов верны. Но 59 отвлечений из 93 система пропускает, и стоимость ошибок 2958. Ответ «никогда не тревожить» верен в 95,4 % случаев — почти так же «хорошо» — и стоит 4650. Порог 0,47 даёт всего 79,6 % верных ответов: зря тревожит 398 раз. Зато пропускает только 9 отвлечений, и стоимость падает до 848 — в три с половиной раза меньше.

Когда один вид ошибок встречается редко, а стоит дорого, доля верных обманывает. Порог выбирают по суммарной стоимости ошибок, а саму стоимость задают люди: технолог, юрист, руководитель. Это решение не модели.

## Ошибки по группам

Модель может ошибаться в среднем редко, но чаще — для какой-то группы людей. Возьмём перепись США 1994 года из урока 7.9. Модель по анкете предсказывает, что доход человека выше 50 тысяч долларов в год. Представим, что по такому прогнозу банк решает, кому предложить выгодный продукт. Проверим ошибки отдельно для женщин и мужчин:

```python
adult = pd.read_csv('adult.csv')
y = (adult['salary'] == '>50K').astype(int).to_numpy()
num = ['age', 'education-num', 'hours-per-week', 'capital-gain', 'capital-loss']
cat = ['workclass', 'marital-status', 'occupation', 'relationship', 'race', 'sex']
X_tr, X_te, y_tr, y_te = train_test_split(adult[num + cat], y, test_size=0.3, random_state=0, stratify=y)

def make_model(cats):
    return make_pipeline(make_column_transformer((StandardScaler(), num), (OneHotEncoder(handle_unknown='ignore'), cats)),
                         LogisticRegression(max_iter=1000))

model = make_model(cat).fit(X_tr, y_tr)
pred = model.predict(X_te)
print('доля верных на проверке:', round((pred == y_te).mean(), 3))

def rates(t, p):
    return pd.Series({'доход >50K': t.mean(), 'выбрано': p.mean(), 'доля верных': (t == p).mean(),
                      'пропуски': ((p == 0) & (t == 1)).sum() / (t == 1).sum(),
                      'ложные': ((p == 1) & (t == 0)).sum() / (t == 0).sum()})

sex = X_te['sex'].to_numpy()
pd.DataFrame({g: rates(y_te[sex == g], pred[sex == g]) for g in ['Female', 'Male']}).T.round(3)
```

Здесь две доли ошибок, как у детектора:

- **доля пропусков** (false negative rate, FNR) — среди людей с доходом выше 50 тысяч, сколько модель не отобрала;
- **доля ложных срабатываний** (false positive rate, FPR) — среди людей с доходом ниже, сколько модель отобрала.

Доля верных у женщин выше — 93 % против 81 %. Но это потому, что доход выше 50 тысяч в этих данных у 11 % женщин и у 31 % мужчин: угадать «нет» для женщины проще. Пропусков же у женщин больше: модель не замечает 47 % женщин с высоким доходом против 40 % мужчин. Одной общей цифры — 85 % верных — не видно ни того, ни другого.

## Убрать колонку «пол» — не решение

Кажется, проще всего не показывать модели пол:

```python
model_ns = make_model([c for c in cat if c != 'sex']).fit(X_tr, y_tr)
pred_ns = model_ns.predict(X_te)
print(pd.DataFrame({g: rates(y_te[sex == g], pred_ns[sex == g]) for g in ['Female', 'Male']}).T.round(3)[['пропуски', 'ложные']])
print(pd.crosstab(adult['relationship'], adult['sex']))
```

Разрыв почти не изменился: пропусков у женщин 45 %, у мужчин 40 %. Пол модель узнаёт по другим признакам. В колонке `relationship` значение `Husband` («муж») стоит у 13 192 мужчин и одной женщины, `Wife` («жена») — у 1566 женщин и двух мужчин. Убрали одну колонку — информация осталась в другой. Если убрать и её, разрыв даже растёт: модель теряет полезный признак, и сильнее всего это бьёт по меньшей группе.

Что делают на практике: меряют ошибки по группам до запуска, ищут, откуда разрыв (данные, признаки, сама разметка), и решают, какие ошибки допустимы. Выровнять все доли ошибок сразу обычно нельзя: выравнивание пропусков раздвигает ложные срабатывания — это вы увидите в задании со звёздочкой.

## Личные данные

Модели учатся на данных людей, а ассистентам люди сами пишут о себе. Риски здесь такие:

- **тексты** с именами, телефонами и адресами уходят во внешний сервис. Мы уже знаем из модуля 10: личные данные в чужую модель не отправляют;
- **лица и голоса** — биометрия. Закон о персональных данных (152-ФЗ) выделяет её отдельно: обрабатывать её можно только с согласия человека, за исключениями, которые закон перечисляет;
- **подделки**. Синтез голоса из урока 12.5 и генерация видео (лекция, слайды 10 и 38) позволяют подделать человека. Звонок «от родственника» его клонированным голосом — уже реальный способ мошенничества. Поэтому сгенерированное помечают, а важные просьбы проверяют по другому каналу: перезванивают сами.

Тексты перед отправкой **обезличивают** — заменяют личные данные метками. Это задача выделения сущностей из урока 12.4:

```python
message = ('Здравствуйте! Я Анна Петрова, мой телефон +7 000 111-22-33, почта anna.petrova@example.ru. '
           'Перезвоните, пожалуйста, или напишите Ивану: 8 (000) 765-43-21. Анне передайте спасибо.')
names = ['Анна', 'Петрова', 'Иван']
masked = re.sub(r'[\w.+-]+@[\w-]+(?:\.[\w-]+)+', '[ПОЧТА]', message)
masked = re.sub(r'(?:\+7|\b8)[\s(-]*\d{3}[\s)-]*\d{3}[\s-]*\d{2}[\s-]*\d{2}', '[ТЕЛЕФОН]', masked)
masked = re.sub(r'\b(?:' + '|'.join(names) + r')[а-яё]{0,3}\b', '[ИМЯ]', masked)
print(masked)
```

Данные выдуманы: телефонного кода 000 не существует, а домен example.ru зарезервирован для примеров. Почта и телефоны заменены, «Ивану» найдено по правилу «имя и окончание». А «Анне» осталось: при склонении у «Анны» меняется последняя буква, и правило «имя + окончание» её не узнаёт. Обезличивание правилами всегда что-то пропускает. Поэтому его дополняют моделями выделения сущностей, а важные наборы данных проверяют выборочно вручную. Кроме того, человека выдают не только имя и телефон, но и сочетание признаков: должность, город и возраст вместе.

## Типичные ошибки

:::mistake Выбирать порог по доле верных
Когда пропуск стоит в 50 раз дороже ложной тревоги, лучший по доле верных порог оказался втрое дороже лучшего по стоимости. Сначала спросите, сколько стоит каждая ошибка.
:::

:::mistake Смотреть только на общую цифру
85 % верных в среднем скрывали, что женщин с высоким доходом модель пропускает чаще, чем мужчин. Считайте доли пропусков и ложных срабатываний отдельно для групп.
:::

:::mistake Считать, что без колонки «пол» модель беспристрастна
Пол выдают другие признаки — здесь «муж» и «жена» в `relationship`. Проверять нужно ошибки модели, а не список её признаков.
:::

## Что запомнить

- Пять технологий ИИ по национальной стратегии: зрение, язык, речь, поддержка принятия решений, перспективные методы. Технологию выбирают по данным задачи.
- Ошибки стоят по-разному: порог выбирают по суммарной стоимости ошибок, а стоимость задают люди.
- Качество проверяют по группам: при одной общей доле верных пропуски и ложные срабатывания в группах различаются.
- Удаление чувствительного признака не убирает разрыв: его выдают другие признаки.
- Личные данные убирают из текстов до отправки во внешние сервисы, биометрию защищает закон, а сгенерированное помечают.
