## Зачем это нужно

Технологии ИИ из лекции работают с тремя видами данных, кроме таблиц:

- **картинки** — двумерная таблица пикселей (у цветной на каждый пиксель три числа);
- **тексты** — последовательности слов, которые мы уже превращали в векторы (модули 9 и 11);
- **звук** — длинный ряд отсчётов (урок 11.8).

Над картинкой и звуком работают те же операции NumPy, что над столбцами таблицы в модуле 1. Вырезать кусок картинки — срез. Найти яркие пиксели — маска. Средняя яркость каждой строки — среднее по оси. Повторим их на игрушечной «картинке», которую программа рисует сама.

## Картинка — двумерный массив

```python
print('форма:', scene.shape, '| от', scene.min().round(3), 'до', scene.max().round(3))
print('пиксель в строке 10, столбце 15:', scene[10, 15].round(3))
plt.figure(figsize=(5, 3.4))
plt.imshow(scene, cmap='gray')
plt.colorbar(label='яркость')
plt.title('Прямоугольник, круг и слабый шум')
plt.show()
```

Массив `40 × 60` — 40 строк и 60 столбцов. Первый индекс — строка, то есть координата сверху вниз; второй — столбец, слева направо. `plt.imshow` рисует массив как картинку: чем больше число, тем светлее пиксель.

## Срезы: вырезать и отразить

```python
crop = scene[5:23, 7:28]                   # строки 5–22, столбцы 7–27
flipped = scene[:, ::-1]                   # отражение слева направо
print('вырезано:', crop.shape, '| отражено:', flipped.shape)
print('левый верхний угол прямоугольника до и после отражения:', scene[8, 10].round(2), flipped[8, 60 - 1 - 10].round(2))
```

Срез `[строки, столбцы]` вырезает прямоугольный кусок, как в уроке 1.3. Шаг `-1` идёт в обратном порядке: `[:, ::-1]` отражает картинку по горизонтали. Пиксель из столбца 10 после отражения оказывается в столбце 60 − 1 − 10 = 49.

## Маска: где ярко

```python
bright = scene > 0.5                       # маска того же размера, что картинка
print('ярких пикселей:', bright.sum(), 'из', bright.size, f'({bright.mean():.1%})')
rows = np.nonzero(bright.any(axis=1))[0]   # строки, где есть хоть один яркий пиксель
cols = np.nonzero(bright.any(axis=0))[0]
print('яркое — в строках', rows.min(), '…', rows.max(), 'и столбцах', cols.min(), '…', cols.max())
```

`bright` — маска из `True` и `False`. Сумма маски — число ярких пикселей, среднее — их доля (урок 1.5). `any(axis=1)` спрашивает для каждой строки: «есть ли в ней яркий пиксель?» — так находится, где на картинке начинаются и кончаются объекты. В уроке 12.2 на этой идее построим рамку вокруг объекта.

## Оси и действия сразу над всем массивом

```python
row_mean = scene.mean(axis=1)              # средняя яркость каждой строки — 40 чисел
col_mean = scene.mean(axis=0)              # каждого столбца — 60 чисел
print('самая яркая строка:', row_mean.argmax(), '| самый яркий столбец:', col_mean.argmax())
norm = (scene - scene.min()) / (scene.max() - scene.min())     # растянуть яркость до 0…1
centered = scene - col_mean                # из каждого столбца вычесть его среднее: (40, 60) − (60,)
print(norm.min(), norm.max(), '| форма после вычитания:', centered.shape)
```

`axis=1` сворачивает строку в одно число, `axis=0` — столбец (урок 1.10). Вычитание `scene - col_mean` работает без цикла: массив из 60 средних «растягивается» на все 40 строк — это broadcasting.

## Звук — одномерный массив

```python
rate = 8000                                 # отсчётов в секунду
t = np.arange(int(rate * 0.5)) / rate       # 0,5 секунды
wave_440 = np.sin(2 * np.pi * 440 * t)      # чистый тон 440 Гц — нота ля
print('отсчётов:', len(wave_440), '| первые:', wave_440[:5].round(3))
crossings = np.sum(np.sign(wave_440[:-1]) != np.sign(wave_440[1:]))
print('смен знака:', crossings, '→ частота ≈', crossings / 2 / 0.5, 'Гц')
```

Звук из урока 11.8 — отсчёты, по `rate` штук в секунду. Синусоида с частотой 440 Гц за секунду 440 раз поднимается и опускается и дважды за период меняет знак. Поэтому число смен знака, делённое на 2 и на длительность, даёт частоту. Для чистого тона это работает, а для речи — смеси многих частот — нужен спектр, он будет в уроке 12.5.

## Повторим: честная проверка модели

В уроках 12.3 и 12.6 мы будем обучать и проверять классификаторы. Вспомним три правила из модуля 5:

- **обучение, валидация, тест** (урок 5.3). Модель учится на обучающей части, модель и гиперпараметры выбирают по валидационной, а тестовую открывают один раз в конце. Качество на обучающей части ничего не говорит о новых данных: модель могла запомнить ответы.
- **Утечка данных** (урок 5.4) — в обучение попало то, чего не будет при настоящем применении. Например, признак, вычисленный по ответу, масштабирование по всем данным до разбиения или почти одинаковые объекты по разные стороны разбиения. Оценка с утечкой выглядит лучше, чем модель покажет на деле.
- **Ориентир** (урок 5.5) — простейший ответ вроде «всегда самый частый класс». Модель имеет смысл, только если обгоняет его.

Для урока 12.6 вспомним **бинарную классификацию** (урок 8.7). Модель даёт вероятность класса 1, а класс выбирают по порогу — обычно 0,5. Ошибки бывают двух видов: пропуск (на самом деле 1, а модель сказала 0) и ложное срабатывание (на самом деле 0, а модель сказала 1).

И ещё одно понятие из модуля 9 понадобится в уроке о речи. **Языковая модель на парах слов** (урок 9.1) оценивает вероятность следующего слова по тому, как часто пара слов встречалась в текстах: P(«лес» | «случайный») = число пар «случайный лес» / число слов «случайный». Вероятность фразы — произведение таких вероятностей по соседним парам.

А для мини-проекта вспомним **zero-shot классификацию** CLIP (урок 9.7). Картинку и подписи-кандидаты модель переводит в векторы одного пространства. Ответ — подпись с наибольшим косинусным сходством, и обучать модель на своих классах не нужно.
