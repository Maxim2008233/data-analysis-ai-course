## Зачем это нужно

ChatGPT, GigaChat, Алиса — это **диалоговые системы**, как сказано на слайдах лекции: большая языковая модель плюс интерфейс. Интерфейс получает вопрос пользователя, отправляет его модели, показывает ответ и хранит историю диалога.

Программа может обратиться к той же модели напрямую — через **API**. Это запрос по сети в определённом формате. Так модели встраивают в свои приложения: чат-бот поддержки, разбор отзывов, автоматический ответ на тест. Чтобы писать такие программы, нужно знать, из чего состоят запрос и ответ.

## Ключ — не в коде

У каждого запроса к GigaChat есть **ключ авторизации** из личного кабинета Сбера. По нему сервис понимает, кто спрашивает и с кого списывать токены. Ключ — как пароль: в ноутбуке курса его читают из отдельного файла `authGigaChat.txt`. Его не пишут в коде, не отправляют в чат и не выкладывают на GitHub.

Поэтому на этом сайте настоящего GigaChat нет: ключ в коде сайта увидел бы любой. В браузере работает **учебная версия** библиотеки `gigachat`. Запросы она не отправляет, а возвращает ответы GigaChat, записанные в ноутбуке курса, — для тех же запросов, что в ноутбуке. Свои запросы отправляйте из [ноутбука курса в Colab](https://colab.research.google.com/github/MVRonkin/BasicDataAnalysisCourse/blob/main/Workshops/2025/06_PromptEng.ipynb) со своим ключом.

## Первый запрос

Код из ноутбука курса — как есть:

```python
from gigachat import GigaChat

with GigaChat(credentials='ваш-ключ', verify_ssl_certs=False) as giga:
    response = giga.chat(MESSAGE)

print(response.choices[0].message.content)
```

Это настоящий ответ GigaChat из ноутбука. `GigaChat(...)` создаёт клиента: `credentials` — ключ, `verify_ssl_certs=False` отключает проверку сертификата. Это небезопасно, и в ноутбуке так сделано лишь ради простоты. `giga.chat(текст)` отправляет вопрос и ждёт ответ. Конструкция `with` закрывает соединение, когда блок кончится.

## Что внутри ответа

```python
with GigaChat(credentials='ваш-ключ', verify_ssl_certs=False) as giga:
    response = giga.chat(MESSAGE)
choice = response.choices[0]
print('Модель:', response.model)
print('Роль автора ответа:', choice.message.role)
print('Причина остановки:', choice.finish_reason)
print('Начало ответа:', choice.message.content[:90])
```

Ответ API — объект с несколькими полями:

- `choices` — список вариантов ответа, обычно из одного. В нём `message` — сообщение модели с ролью `assistant` и текстом `content`, и `finish_reason` — почему модель остановилась: `stop` — закончила сама, `length` — упёрлась в лимит длины, `function_call` — хочет вызвать функцию (урок 10.6);
- `model` — какая модель ответила;
- `usage` — сколько токенов ушло на запрос и ответ (урок 9.5). По ним считается оплата.

Сравните текст с предыдущим примером: это **другой** ответ на тот же вопрос. В ноутбуке записаны два разных ответа GigaChat на одинаковый запрос, и учебная версия выдаёт их по очереди. Модель выбирает слова случайно, поэтому ответы на одинаковые запросы различаются. Почему — в уроке 10.2.

## Запрос как объект Chat

Вместо строки можно передать весь запрос — объект `Chat`:

```python
from gigachat.models import Chat, Messages, MessagesRole

payload = Chat(
    messages=[
        Messages(role=MessagesRole.SYSTEM, content=SYSTEM),
        Messages(role=MessagesRole.USER, content=MESSAGE),
    ],
    temperature=0.7,
    max_tokens=100,
)
print(json.dumps(payload.dict(exclude_none=True), ensure_ascii=False, indent=1)[:600])
```

Так запрос и уходит на сервер — словарём в формате JSON:

- `messages` — история диалога, список сообщений с ролями: `system` — инструкция модели, `user` — вопрос человека, `assistant` — ответ модели (подробно — урок 10.3);
- `temperature` — насколько случайно модель выбирает слова (урок 10.2);
- `max_tokens` — наибольшая длина ответа в токенах.

## max_tokens обрывает ответ

```python
model = GigaChat(model='GigaChat-2-Pro', credentials='ваш-ключ', verify_ssl_certs=False)
response = model.chat(payload)
print(response.choices[0].finish_reason)
print(response.choices[0].message.content)
```

Модель обещала «3 коротких пункта», а оборвалась на втором: лимит в 100 токенов кончился. `finish_reason = 'length'` сообщает об этом программе. Обрыв на полуслове — частая беда в приложениях. Проверяйте `finish_reason`, а лимит ставьте с запасом.

В ноутбуке есть и обратный случай. Там собран `payload` с `max_tokens=100`, а в `model.chat` передана строка `MESSAGE`. Параметры до модели не дошли, и ответ получился полной длины. Модель не предупреждает, что параметры потерялись, — это видно только по коду.

## Свой запрос

Запроса, которого нет в ноутбуке, учебная версия не знает и объясняет почему:

```python expect-error
with GigaChat(credentials='ваш-ключ', verify_ssl_certs=False) as giga:
    giga.chat('Объясни, что такое токен, в одном предложении')
```

## Типичные ошибки

:::mistake Ключ в коде
Строка `credentials='MjI4...'` в ноутбуке, который вы отправили преподавателю или выложили на GitHub, — это утечка: по ключу другие тратят ваши токены. Храните ключ в отдельном файле или переменной окружения.
:::

:::mistake Не проверять finish_reason
Ответ с `finish_reason = 'length'` оборван на полуслове. Программа, которая его не проверяет, покажет пользователю обрубок или разберёт половину JSON.
:::

:::mistake Собрать параметры и не передать их
`Chat(..., max_tokens=100)` работает, только если передать в `chat` сам этот объект. Передали строку — модель получила только текст и параметры по умолчанию.
:::

## Что запомнить

- Запрос к чат-модели — список сообщений с ролями (system, user, assistant) и параметры: модель, temperature, max_tokens.
- Ответ — `choices[0].message.content`, причина остановки `finish_reason` (stop, length, function_call) и расход токенов `usage`.
- Ключ авторизации — как пароль: не в коде и не в репозитории.
- Проверяйте `finish_reason` и то, что собранный `Chat` действительно передан в запрос.
