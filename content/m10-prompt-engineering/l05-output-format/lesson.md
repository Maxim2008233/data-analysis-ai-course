## Зачем это нужно

Модель отвечает текстом, а программе нужно значение: номер варианта, число, словарь с полями. Между ними — две задачи:

- **попросить формат** — так ясно, чтобы модель почти всегда отвечала как нужно;
- **проверить ответ** — разобрать его программой, убедиться, что значение допустимо, и решить, что делать, если нет.

Модель иногда нарушает любой формат, поэтому одной просьбы мало: проверка нужна всегда.

## «Первое число» ломается

Базовое решение соревнования берёт из ответа первое число: `int(re.findall(r'\d+', ответ)[0])`. Проверим это правило на настоящих ответах GigaChat из ноутбука курса:

```python
for key in ['calc-final', 'cot-1', 'cot-2']:
    text = notebook[key]['response']
    numbers = re.findall(r'\d+', text)
    tail = text[text.rfind('Ответ'):] if 'Ответ' in text else text     # текст от последнего «Ответ»
    after = re.findall(r'\d+', tail)
    print(f'{key:10} первое: {numbers[0]:>3} | последнее: {numbers[-1]:>3} | после «Ответ»: {after[0] if after else None}')
print(notebook['calc-final']['response'])
```

Ответ калькулятора — «Результат выражения 3*(4+5)**2 равен 243», и первое число в нём — 3 из самого выражения. В рассуждениях «шаг за шагом» первое число — номер шага, 1. Здесь выручает последнее число или число после слова «Ответ». Но и это правило сломается на ответе «Вариант 2, это 1662 год». Угадывать формат по тексту ненадёжно — его нужно задать.

## Что получилось на тесте

У нас есть прогнозы базового решения на 786 вопросах теста — номера, которые оно достало из ответов GigaChat. Правильных ответов теста нет, но кое-что видно и без них: номер варианта должен быть от 0 до числа вариантов минус один.

```python
test = pd.read_csv('qa_test.csv')
pred = pd.read_csv('qa_gigachat_baseline.csv')
test['options'] = test['варианты'].apply(parse_options)
test['n'] = test['options'].apply(lambda o: len(o) if o is not None else 0)
df = test.merge(pred, on='id')
df['valid'] = (df['prediction'] >= 0) & (df['prediction'] < df['n'])
print('Прогнозов:', len(df), '| недопустимых:', (~df['valid']).sum(), f"({(~df['valid']).mean():.1%})")
print(df.loc[~df['valid'], 'prediction'].value_counts().head(6))
print('четыре варианта, а прогноз 4:', ((df['n'] == 4) & (df['prediction'] == 4)).sum())
```

96 прогнозов из 786 — 12,2 % — заведомо неверны: такого номера у вопроса нет. Чаще всего это «4» у вопроса с четырьмя вариантами, 30 раз. Скорее всего, модель считала варианты с единицы, хотя промпт просил «считая от 0». Есть и прогнозы 2025 и 2023 — это годы. Откуда берутся большие числа, видно по вопросам:

```python
for _, r in df[~df['valid'] & (df['prediction'] > 10)].head(5).iterrows():
    print(f"{r['prediction']:>5} ← {r['вопрос']}")
```

«Сколько будет √64?» — и прогноз 64: в ответе модели раньше номера варианта встретилось число из вопроса, и правило взяло его. Молярная масса NaCl — прогноз 23: видимо, первой в ответе стояла масса натрия. У трёх вопросов варианты в файле вообще не разбираются: вместо списка там текст вопроса или формулы с апострофом внутри кавычек. Программа не может проверить для них ни один номер, поэтому и они попали в недопустимые.

## Попросить формат

Формат задают в промпте явно и проверяемо:

- **одна цифра** — «Ответь одной цифрой от 0 до 3 — номером правильного варианта, без пояснений»;
- **JSON** — «Ответь только JSON без пояснений: {"answer": номер}» (урок 10.4: в шаблоне скобки удваивают);
- **примеры** — few-shot с ответами ровно в нужном формате показывают его лучше слов (урок 10.4);
- **номера в вариантах** — пронумерованные варианты `0) … 3)` подсказывают и допустимые значения.

## Строгий разбор

Если формат задан, ответ разбирают строго: подходит только он, а всё остальное — ошибка. Так ошибки видны, а не прячутся за случайным числом:

```python
def parse_digit(text, n):
    m = re.fullmatch(r'\s*(\d+)\s*\.?\s*', text)       # весь ответ — одно число (точка в конце допустима)
    if m is None:
        return None
    k = int(m.group(1))
    return k if k < n else None

for text in ['2', ' 3. ', 'Ответ: 2', '4', 'Вариант 1 — 1662 год']:
    print(f'{text!r:25} → {parse_digit(text, 4)}')
```

`re.fullmatch` требует, чтобы шаблон совпал со **всей** строкой, а не с её кусочком, как `findall`. `None` значит «ответ не по формату» — дальше программа решает, что с этим делать. «Ответ: 2» строгий разбор не принял. Если такие ответы частые, можно разрешить и их, но явно, а не любое первое число.

## JSON

Ответ-словарь разбирает `json.loads`. Модели часто оборачивают JSON в блок кода markdown: перед ним строка из трёх обратных кавычек и слова json, после — снова три обратные кавычки. Эту обёртку снимают перед разбором, а ошибку разбора ловят:

```python
fence = '`' * 3                                   # три обратные кавычки — рамка блока кода

def parse_json(text):
    text = text.strip().removeprefix(fence + 'json').removesuffix(fence)
    try:
        return json.loads(text)
    except json.JSONDecodeError:
        return None

for text in ['{"answer": 2}', fence + 'json\n{"answer": 0}\n' + fence, "{'answer': 1}", 'Ответ: {"answer": 3}']:
    print(f'{text!r:32} → {parse_json(text)}')
```

Одинарные кавычки — не JSON, и текст перед скобкой тоже мешает. Разобранный словарь ещё нужно проверить: есть ли ключ `answer`, число ли там и допустимо ли оно.

## Если ответ не подошёл

Неподходящий ответ — не повод сдаваться. Варианты:

- **переспросить**: добавить в историю ответ модели и уточнение, что формат нарушен (урок 10.3);
- **поставить запасной ответ** — например, самый частый вариант, и пометить его;
- **считать долю** таких ответов: если она большая, менять промпт.

Пусть модель ответила целым предложением. Переспросим:

```python
history = [{'role': 'system', 'content': 'Ты решаешь тест. Отвечай одной цифрой — номером правильного варианта.'},
           {'role': 'user', 'content': 'Вопрос: Сколько часов в 180 минутах?\nВарианты ответа:\n0) 3\n1) 2\n2) 4\n3) 5\nОтвет:'}]
bad_answer = 'В 180 минутах 3 часа, это вариант 0.'               # пример ответа не по формату
if parse_digit(bad_answer, 4) is None:
    history = history + [{'role': 'assistant', 'content': bad_answer},
                         {'role': 'user', 'content': 'Ответь только одной цифрой от 0 до 3, без пояснений.'}]
for m in history:
    print(f"{m['role']:9} | {m['content'][:60]!r}")
```

Модель видит свой прошлый ответ и просьбу исправить формат. Повторный запрос стоит токенов, поэтому число попыток ограничивают.

## Типичные ошибки

:::mistake Брать первое число из свободного текста
Первым числом оказывается номер шага, число из вопроса или год. На тесте соревнования так получилось 96 заведомо неверных прогнозов из 786.
:::

:::mistake Разбирать без проверки допустимости
Разобранное число ещё не ответ: номер 4 у вопроса с четырьмя вариантами невозможен. Проверяйте, что значение лежит в допустимых границах.
:::

:::mistake Не ловить ошибку json.loads
Модель хотя бы иногда ответит не JSON, и `json.loads` упадёт — а с ним и вся обработка 786 вопросов. Разбор оборачивают в `try` / `except`.
:::

## Что запомнить

- Формат ответа задают явно: одна цифра или JSON с нужными полями, лучше вместе с примерами.
- Ответ разбирают строго (`re.fullmatch`, `json.loads` в `try`) и проверяют допустимость значения.
- «Первое число в тексте» ломается на номерах шагов, годах и числах из вопроса.
- Если ответ не по формату — переспрашивают ограниченное число раз или ставят запасной ответ и считают долю таких случаев.
