## Зачем это нужно

Языковая модель знает только то, что было в её обучающих текстах. Свежих новостей, курса валют, вашего расписания она не знает, а большие числа «в уме» перемножает с ошибками. На лекции про агентов был пример: на просьбу «Покажи расписание моих занятий на завтра» модель честно отвечает, что доступа к расписанию у неё нет.

**Вызов функций** (function calling) решает это так:

1. Вместе с сообщениями программа передаёт модели **описания функций**, которые готова выполнить.
2. Модель решает: ответить сразу или попросить вызвать функцию. Во втором случае она возвращает **вызов** — имя функции и аргументы, а `finish_reason` равен `'function_call'`.
3. Программа сама выполняет функцию и отправляет результат модели сообщением с ролью `function`.
4. Модель формулирует окончательный ответ.

Модель ничего не выполняет сама — она только просит. Выполняет ваша программа.

## Описание функции

В ноутбуке курса модель учат пользоваться калькулятором. Описание функции — как документация, которую модель «читает», прежде чем решить, звать ли функцию:

```python
calculate_func = Function(
    name='calculate',
    description="Выполняет математические вычисления. Передавай ТОЛЬКО выражение в виде строки, например: '2 + 3 * 4'.",
    parameters=FunctionParameters(
        type='object',
        properties={'expression': {'type': 'string',
                                   'description': 'Математическое выражение (только цифры, +, -, *, /, **, скобки)'}},
        required=['expression'],
    ),
)
print(json.dumps(calculate_func.dict(exclude_none=True), ensure_ascii=False, indent=1))
```

- `name` — имя, по которому модель вызовет функцию;
- `description` — когда и зачем её звать. От описания зависит, позовёт ли модель функцию вообще. В ноутбуке есть упражнение: замените описание поиска на «Никогда не используй этот поиск» и посмотрите, что изменится;
- `parameters` — аргументы в формате **JSON Schema**: объект (`object`) с полями `properties`, их типами и списком обязательных `required`.

## Сама функция

Функцию пишете вы. Калькулятор из ноутбука:

```python
def safe_calculate(expression: str) -> str:
    if not re.fullmatch(r'[\d+\-*/().\s]+', expression):          # только цифры, операции и скобки
        return 'Ошибка: выражение содержит недопустимые символы.'
    try:
        if '^' in expression or len(expression) > 50:              # «не даём выполнить 9**9**9»
            return 'Ошибка: выражение слишком сложное или длинное.'
        result = eval(expression, {'__builtins__': {}}, {})
        return str(result)
    except Exception as e:
        return f'Ошибка вычисления: {e}'

for expr in ['3*(4+5)**2', '1/0', "__import__('os')"]:
    print(f'{expr!r:20} → {safe_calculate(expr)}')
```

Аргументы придумывает модель, поэтому функция проверяет их, как любой ввод пользователя. Регулярное выражение пропускает только цифры, знаки операций и скобки — `__import__('os')` не пройдёт. Ошибка возвращается строкой: модель прочитает её и объяснит пользователю.

Но в проверке есть дыра. Комментарий обещает не дать выполнить `9**9**9`, а проверяется символ `^`. В Python степень — это `**`, а `^` — совсем другая операция. Проверим, не вычисляя:

```python
expr = '9**9**9'
print('символы допустимы:', bool(re.fullmatch(r'[\d+\-*/().\s]+', expr)))
print('есть ^:', '^' in expr, '| длиннее 50:', len(expr) > 50)
print('цифр в результате было бы', int(9**9 * math.log10(9)) + 1)     # 9**9**9 = 9**(9**9): число цифр — по логарифму
```

Выражение проходит все проверки, и `eval` начал бы вычислять число из 370 миллионов цифр — программа зависла бы. Исправить калькулятор — задание со звёздочкой.

## Обмен сообщениями

Если модель решила вызвать функцию, её ответ выглядит так. Аргументы вызова в ноутбуке не напечатаны, поэтому здесь они — пример:

```python
call = Messages(role=MessagesRole.ASSISTANT, content='',
                function_call=FunctionCall(name='calculate', arguments={'expression': '3*(4+5)**2'}))
resp = Choices(message=call, finish_reason='function_call')

messages = [Messages(role=MessagesRole.USER, content='Сколько будет 3*(4+5)**2')]
if resp.finish_reason == 'function_call':                       # код ноутбука: модель просит функцию
    func = resp.message.function_call
    if func.name == 'calculate':
        result = safe_calculate(func.arguments.get('expression', ''))
        messages.extend([resp.message, Messages(role=MessagesRole.FUNCTION, content=result)])
second = Chat(messages=messages)
print(json.dumps(second.dict(exclude_none=True), ensure_ascii=False, indent=1))
print('Ответ GigaChat из ноутбука:', notebook['calc-final']['response'])
```

Во втором запросе три сообщения: вопрос, просьба модели вызвать функцию и результат с ролью `function`. Модель видит, что вызов был, и видит результат — и пишет ответ: «Результат выражения 3*(4+5)**2 равен 243». Это настоящий ответ GigaChat из ноутбука.

Если модель ответила сразу, `finish_reason` будет `'stop'`, и программа просто берёт текст. В ноутбуке на этот случай есть ветка `else`.

## Типичные ошибки

:::mistake Выполнять аргументы модели без проверки
Аргументы придумывает модель, и они могут оказаться любыми. `eval`, команды системы и запросы к базе данных с такими аргументами — дыра. Проверяйте всё, а опасные вычисления ограничивайте, иначе `9**9**9` повесит программу.
:::

:::mistake Отправить результат без вызова
Результат функции идёт в историю после сообщения модели с `function_call`. Без него модель не поймёт, откуда взялось число 243 и на какой вопрос оно отвечает.
:::

:::mistake Ждать вызова всегда
Модель может ответить сразу — тогда `finish_reason` равен `'stop'`, а `function_call` пустой. Код должен обработать оба случая.
:::

## Что запомнить

- В запрос передают описания функций: имя, описание и аргументы в JSON Schema.
- Модель отвечает вызовом (`finish_reason = 'function_call'`): именем и аргументами. Выполняет функцию программа.
- Результат возвращают сообщением с ролью `function` после сообщения модели с вызовом и снова спрашивают модель.
- Аргументы модели — непроверенные данные: проверяйте их и ограничивайте опасные вычисления.
