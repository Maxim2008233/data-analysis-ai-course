# Как разместить сайт на Vercel — пошагово

Инструкция для новичка: от установки программ до работающего сайта с аккаунтами. Если что-то пойдёт не так —
загляните в раздел «Частые ошибки» в конце.

Понадобятся три бесплатных аккаунта: **GitHub** (хранит код), **Supabase** (аккаунты и прогресс учеников),
**Vercel** (размещает сайт).

---

## 1. Что установить

1. **Node.js LTS** — https://nodejs.org → кнопка «LTS». Подойдёт версия 20 или новее.
2. **Git** — https://git-scm.com/downloads.

Проверьте в терминале (macOS: «Терминал», Windows: «PowerShell»):

```bash
node -v
```

```bash
npm -v
```

```bash
git --version
```

Должны появиться номера версий, например `v24.11.0`, `11.6.0`, `git version 2.47.0`.

## 2. Запуск на своём компьютере

В папке проекта:

```bash
npm install
```

Создайте файл настроек по образцу (на Windows — скопируйте файл вручную и переименуйте):

```bash
cp .env.example .env.local
```

Запустите сайт:

```bash
npm run dev
```

Откройте http://localhost:3000. Пока в `.env.local` нет ключей Supabase, сайт работает в **гостевом режиме**:
всё доступно, прогресс хранится в браузере, кнопок входа нет. Это нормально — аккаунты подключим в шаге 3.

Первая загрузка Python в браузере занимает несколько секунд (скачивается Pyodide ~10–30 МБ), дальше он берётся из кэша.

## 3. Аккаунты и база данных: Supabase

### 3.1. Создать проект

1. Зайдите на https://supabase.com → **Start your project** → войдите через GitHub.
2. **New project**: придумайте имя (например, `ds-course`), задайте **Database Password** (сохраните его),
   **Region** — ближайший (например, Frankfurt), тариф **Free** → **Create new project**. Подождите пару минут.

### 3.2. Взять адрес и ключ

**Project Settings** (шестерёнка слева) → **API** (или **Data API**):

- **Project URL** → это `NEXT_PUBLIC_SUPABASE_URL`;
- **anon public** (или **Publishable key**) → это `NEXT_PUBLIC_SUPABASE_ANON_KEY`.

Запишите их в `.env.local`:

```
NEXT_PUBLIC_SUPABASE_URL=https://abcdefgh.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...
```

Anon-ключ публичный — он попадает в браузер, и это безопасно: данные защищены правилами доступа (RLS).
Ключ **service_role** — секретный: никогда не вставляйте его в код и в переменные с префиксом `NEXT_PUBLIC_`.

### 3.3. Создать таблицы (применить миграции)

Вариант А — через сайт Supabase (проще):

1. Слева **SQL Editor** → **New query**.
2. Откройте в проекте файл `supabase/migrations/20261108000000_progress.sql`, скопируйте весь текст, вставьте → **Run**.
3. Так же выполните по очереди `supabase/migrations/20261109000000_lesson_steps.sql`,
   `supabase/migrations/20261112000000_competitions.sql` (таблица лидеров соревнований) и
   `supabase/migrations/20261121000000_progress_quota.sql` (не больше 3000 записей и 10 МБ прогресса на ученика —
   чтобы один аккаунт не мог заполнить бесплатную базу) и `supabase/migrations/20261121000001_service_role_grants.sql`
   (права сервера сайта на таблицы соревнований: новые облачные проекты Supabase не выдают их сами).
4. Проверьте: **Table Editor** → появились таблицы `profiles`, `progress`, `competition_entries` и
   `competition_submissions`, у всех включён значок **RLS**.

Вариант Б — через командную строку:

```bash
npx supabase login
```

```bash
npx supabase link --project-ref abcdefgh
```

```bash
npx supabase db push --remote
```

(`abcdefgh` — Reference ID проекта, часть адреса перед `.supabase.co`.) Флаг `--remote` обязателен: Supabase CLI 3
без него применяет миграции к локальной базе и пишет «Local database is up to date». Проверить, что облачная база
получила все пять миграций: `npx supabase migration list --remote` — в столбцах local и remote одинаковые номера.

### 3.4. Настроить вход по email

**Authentication** → **Sign In / Providers** → **Email**: должно быть включено.

- **Confirm email** (подтверждение почты): если включено, после регистрации ученику придёт письмо со ссылкой, и войти
  можно только после подтверждения — сайт это показывает. Если выключить, вход работает сразу. Для учебной группы
  удобно выключить, для открытого сайта — оставить включённым.

**Authentication** → **URL Configuration**:

- **Site URL**: адрес сайта на Vercel, например `https://ds-course.vercel.app` (до первого деплоя можно временно
  поставить `http://localhost:3000` и потом поменять);
- **Redirect URLs** → **Add URL**, добавьте обе строки:
  - `http://localhost:3000/**`
  - `https://ds-course.vercel.app/**` (ваш адрес Vercel)

Без этого ссылки из писем (подтверждение, восстановление пароля) будут вести не туда. Не добавляйте сюда чужие
адреса и шаблоны шире своего домена: Supabase отправит ученика только на перечисленные адреса.

**Authentication** → **Sign In / Providers** → **Email** → требования к паролю: поставьте **минимальную длину 8** —
как проверяет сайт (по умолчанию в Supabase — 6). Для открытого сайта оставьте **Confirm email** включённым: тогда
регистрация не выдаёт, занят ли адрес, и плодить аккаунты сложнее.

Перезапустите `npm run dev` — на сайте появятся «Войти» и «Регистрация».

## 4. Код на GitHub

1. На https://github.com → **New repository** → имя, например `ds-course-trainer`, **Private** или **Public** →
   **Create repository** (без README — он уже есть в проекте).
2. В папке проекта:

```bash
git init
```

```bash
git add .
```

```bash
git commit -m "Курс: первые модули"
```

```bash
git branch -M main
```

```bash
git remote add origin https://github.com/ВАШ-ЛОГИН/ds-course-trainer.git
```

```bash
git push -u origin main
```

Файл `.env.local` в репозиторий **не попадёт** — он в `.gitignore`. Так и должно быть: секреты не хранят в коде.

**Ответы соревнований.** Скрытые цены соревнования 1 лежат в `private/competitions/cars-price/answers.json`, классы картинок
соревнования 2 — в `private/competitions/zero-shot/answers.json`. Сайт
никогда не отдаёт их в браузер: файл читает только серверная функция проверки (тест `tests/unit/competition-leak.test.ts`
следит, чтобы ответов не было ни в `public/`, ни в клиентских файлах сборки). Но в **публичном** репозитории их
сможет прочитать любой. Поэтому для настоящего соревнования делайте репозиторий **Private**. Учтите и другое: ответы
выделены из открытых материалов курса (`cars_train.csv` и архив картинок соревнования), — это учебные соревнования, а не призовые.

## 5. Сайт на Vercel

1. https://vercel.com → **Sign Up** → **Continue with GitHub**.
2. **Add New…** → **Project** → выберите репозиторий `ds-course-trainer` → **Import**.
3. **Framework Preset**: Next.js (определится сам). Build Command и Output Directory не трогайте.
4. Раскройте **Environment Variables** и добавьте:

| Имя | Значение | Публичная? |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL из шага 3.2 | да (попадает в браузер) |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public key из шага 3.2 | да (защищено RLS) |
| `NEXT_PUBLIC_REPORT_BUG_URL` | ссылка для «Нашли ошибку?» (форма, issues, почта) | да, необязательно |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role key (там же, где anon key) | **секретная**, необязательно: включает таблицу лидеров соревнований и надёжный лимит отправок для учеников с аккаунтом. Без неё соревнование работает, но без таблицы лидеров |

5. **Deploy**. Через 2–4 минуты появится адрес вида `https://ds-course-trainer.vercel.app`.
6. Вернитесь в Supabase → **URL Configuration** и проверьте, что **Site URL** и **Redirect URLs** содержат именно этот адрес.

## 7. Как обновлять сайт

Любое изменение отправляется так:

```bash
git add .
```

```bash
git commit -m "Что изменилось"
```

```bash
git push
```

Vercel сам пересоберёт сайт за пару минут (вкладка **Deployments**).

Новый урок или задание — это файлы в папке `content/` (формат описан в README.md, разделы «Как добавить урок»
и «Как добавить задание»). Перед отправкой проверьте контент:

```bash
npm run validate
```

Если изменились таблицы базы — новый файл в `supabase/migrations/` и его выполнение в SQL Editor (шаг 3.3).

Данные модуля 9 (`public/data/sst2_logits.json`, `distilbert_attention.npz`, `zs_*`) уже лежат в репозитории, и для
размещения ничего пересчитывать не нужно. Пересобирать их нужно только при смене моделей или картинок: для этого
понадобятся Python 3.10+, PyTorch и около 2,3 ГБ на диске (окружение и модели — в папке `.cache/`, она не попадает в git):

```bash
python3 -m venv .cache/hf-venv && .cache/hf-venv/bin/pip install torch transformers pillow
```

```bash
HF_HOME=$PWD/.cache/hf .cache/hf-venv/bin/python scripts/hf/build_hf_data.py
```

```bash
HF_HOME=$PWD/.cache/hf HF_HUB_OFFLINE=1 .cache/hf-venv/bin/python scripts/hf/verify_stub.py
```

Второй скрипт сверяет учебную версию transformers в браузере с настоящей библиотекой. Ответы второй половины картинок
соревнования 2 скрипт кладёт в `private/` — на сайт они не попадают.

Данные модулей 10 и 11 (`public/data/gigachat_notebook.json`, `qa_*.csv`, `recording.wav`, `voice_bot_notebook.json`)
тоже уже лежат в репозитории. Их собирает обычный Python без сети и без ключей — только из материалов курса:

```bash
python3 scripts/llm/build_llm_data.py
```

Скрипты ищут материалы курса (распакованный архив `BasicDataAnalysisCourse-main`) в папке «Загрузки». Если архив лежит
в другом месте, укажите путь переменной окружения `COURSE_MATERIALS`, например
`COURSE_MATERIALS=/путь/к/BasicDataAnalysisCourse-main python3 scripts/llm/build_llm_data.py`.

Скрытые ответы соревнования 3 собирает тот же обычный Python из таблицы разметки в `private/competitions/qa/`.
После правок в столбце «Исправление» пересоберите их и обновите baseline в `src/lib/competitions/registry.ts` числами,
которые напечатает скрипт (валидатор контента сверяет их с расчётом):

```bash
python3 scripts/llm/build_qa_competition.py
```

База знаний модуля 11 — разделы уроков самого курса. Если вы меняли уроки модулей 0–10, пересоберите её
(`course_docs.json`, `course_queries.json`, `course_glossary.json`) и прогоните проверку модулей 11 и 12 и контрольной
точки 2: числа в их уроках посчитаны на этой базе (классификатор разделов 12.3, сущности и опечатки 12.4, языковая
модель 12.5, мини-проект 12.7, поиск и RAG в КТ 2).

```bash
npx tsx scripts/llm/build_course_docs.ts
npm run validate -- --module m11
npm run validate -- --module m12
npm run validate -- --module k2
```

Размеченные вопросы помощника по курсу (`public/data/assistant_questions.json`) составлены вручную и скриптом не
собираются: при правке сохраняйте половины `dev` (подбор порога, урок 11.3) и `test` (итоговая оценка, урок 11.9).

Данные мини-проекта бонус-модуля (`public/data/water_polution.csv`) — копия файла `addition/water_polution.csv` из
материалов курса (набор лабораторной lab8), без изменений; пересобирать его не нужно. Если файл заменят, прогоните
проверку бонус-модуля: все числа урока Б.7 посчитаны на этой копии.

```bash
npm run validate -- --module b1
```

Ключ GigaChat сайту не нужен и не должен попадать ни в код, ни в переменные Vercel: в браузере работает учебная версия,
которая воспроизводит ответы из ноутбука курса. Свои запросы ученики отправляют из Colab со своим ключом.

## 8. Ограничения бесплатных тарифов

- **Supabase Free**: 500 МБ базы (прогресс одного ученика — десятки килобайт, хватит на тысячи учеников);
  проект «засыпает» после 7 дней без запросов — разбудить кнопкой **Restore** в панели Supabase.
  Встроенная почта отправляет лишь несколько писем в час — для группы больше 20–30 человек подключите свой SMTP:
  **Authentication** → **Emails** → **SMTP Settings** (подойдёт почта Яндекса, Mail.ru, SendGrid, Resend и др.).
- **Vercel Hobby**: для некоммерческого учебного сайта; 100 ГБ трафика в месяц. Pyodide грузится с CDN jsDelivr
  и в этот лимит не входит.
- Если лимиты превышены: Supabase и Vercel предупреждают письмом; можно перейти на платный тариф или подключить свой SMTP.

## 9. Частые ошибки

**Не приходит письмо.** Проверьте «Спам». Посмотрите **Authentication** → **Logs**. Встроенная почта Supabase
ограничена несколькими письмами в час — подключите SMTP (раздел 8). На время занятия можно выключить
**Confirm email** (шаг 3.4).

**После входа по ссылке из письма открывается localhost или ошибка редиректа.** В **URL Configuration** неверный
**Site URL** или нет адреса в **Redirect URLs**. Добавьте `https://ваш-адрес.vercel.app/**` и запросите письмо заново.

**На сайте нет кнопок входа.** Не заданы переменные `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY`
в Vercel (**Settings** → **Environment Variables**). После добавления нужен новый деплой:
**Deployments** → «…» → **Redeploy**.

**«Не удалось сохранить прогресс» / ошибки синхронизации.** Не выполнены миграции (шаг 3.3) — в **Table Editor**
должны быть таблицы `profiles` и `progress`.

**Не грузится Python (Pyodide).** Нужен доступ к `cdn.jsdelivr.net`: в некоторых учебных сетях он закрыт — проверьте
с мобильного интернета. Очень старые браузеры не поддерживаются: нужен Chrome/Edge/Firefox/Safari последних двух лет.
Иногда помогает обновить страницу с очисткой кэша (Ctrl+Shift+R).

**Сборка на Vercel упала.** Откройте лог в **Deployments** → нужная сборка → **Build Logs**. Перед отправкой проверяйте
локально: `npm run build`, `npm run lint`, `npm run typecheck`.

**Ошибка 500 на серверной функции.** **Deployments** → **Functions** (или **Logs**) покажет причину; чаще всего — не
задана переменная окружения для этой функции. Секретные ключи задаются только в Vercel, без префикса `NEXT_PUBLIC_`.

**Нет таблицы лидеров в соревновании.** Не задан `SUPABASE_SERVICE_ROLE_KEY` или не выполнена миграция
`20261112000000_competitions.sql` (шаг 3.3). Проверка прогнозов при этом работает. Сообщение «Таблица лидеров временно
недоступна» — ошибка запроса к базе: смотрите логи функции `/api/competitions/[id]/leaderboard`. Самая частая причина в
новом облачном проекте — у роли `service_role` нет прав на таблицы соревнований: выполните миграцию
`20261121000001_service_role_grants.sql`. Проверить права можно запросом в **SQL Editor**:
`select has_table_privilege('service_role', 'public.competition_entries', 'SELECT');` — должно быть `true`.

**«Лимит — 10 отправок за 24 часа».** Так задумано: соревнование учит проверять идеи на своей validation. Для учеников
с аккаунтом лимит считается по журналу в базе; для гостей — по IP в памяти серверной функции (на Vercel — по
возможности, у каждого экземпляра функции своя память). Изменить лимит — `dailyLimit` в `src/lib/competitions/registry.ts`.
