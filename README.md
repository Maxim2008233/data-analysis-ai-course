# Лаборатория данных — интерактивный курс «Анализ данных и искусственный интеллект»

Сайт: **https://data-analysis-ai-course.vercel.app**

Сайт-тренажёр для студентов первого курса: теория с запускаемыми примерами, задания с автопроверкой прямо в браузере
(Python работает через Pyodide, без установки), подсказки в три уровня, прогресс в браузере или в аккаунте с
синхронизацией между устройствами. Весь основной курс идёт на одном наборе данных — 41 007 объявлений о продаже
автомобилей.

Подробная карта курса (модуль → урок → исходные файлы → новые и используемые понятия) — в [COURSE_MAP.md](COURSE_MAP.md),
размещение на Vercel — в [DEPLOY.md](DEPLOY.md), результаты проверки — в [TEST_REPORT.md](TEST_REPORT.md).

учебный GigaChat не отправляет запросов: для тех же запросов, что в ноутбуке `Workshops/2025/06_PromptEng.ipynb`, он

что его нужно отправить из Colab со своим ключом. Модели запроса (`Chat`, `Messages`, `Function`), шаблоны, цепочки `|`,
парсеры и тестовая `FakeListChatModel` работают как в библиотеках. Данные модуля собирает скрипт
`scripts/llm/build_llm_data.py` (без сети и без ключей): записи ноутбука и запросы, которые их вызвали, вопросы
соревнования QA (`qa_train.csv`, `qa_test.csv`) и прогнозы базового решения на тесте (`qa_gigachat_baseline.csv`).

В модуле 11 к учебным версиям добавились инструменты LangChain: `langchain_core.tools` (`@tool`, схема аргументов из подсказок типов, `parse_docstring`), `langchain_core.utils.function_calling.convert_to_openai_tool`, тестовая модель `FakeMessagesListChatModel`, вызовы `AIMessage.tool_calls` и `ToolMessage` с обязательным `tool_call_id`, `langchain_gigachat.chat_models` и `bind_tools` (в браузере объясняет, что запросы с инструментами нужно отправлять из Colab). Агентов проверяют на тестовой модели с заготовленными ответами, а инструменты в них настоящие. База знаний модуля — разделы уроков самого курса: `course_docs.json`, проверочные запросы `course_queries.json` и справочник `course_glossary.json` собирает `npx tsx scripts/llm/build_course_docs.ts`. Размеченные вопросы для помощника по курсу (`assistant_questions.json`: 30 по курсу с уроками, где есть ответ, и 30 не по курсу, половины dev и test) составили авторы сайта. Для голосового бота `scripts/llm/build_llm_data.py` берёт из ноутбука `Workshops/2025/08_Голосовой_бот_Colab.ipynb` запись `recording.wav`, ответы SaluteSpeech и диалог голосового чата с GigaChat (`voice_bot_notebook.json`); учебный GigaChat воспроизводит этот диалог для тех же сообщений.

Модуль 12 и контрольная точка 2 новых данных не добавляют: они работают на файлах прошлых модулей — миниатюрах и векторах CLIP соревнования 2, разделах уроков `course_docs.json`, записи `recording.wav`, данных Adult, Diabetes, полумесяцах и логитах DistilBERT. ## Быстрый старт

Нужны Node.js 20+ (проверено на 24 LTS) и npm.

```bash
npm install
cp .env.example .env.local   # можно оставить пустым: сайт работает в гостевом режиме
npm run dev                  # http://localhost:3000
```

Без переменных Supabase сайт работает полностью, но прогресс хранится только в браузере (кнопки входа скрыты).
Для аккаунтов поднимите локальный Supabase (нужен Docker):

```bash
npm run db:start             # Supabase в Docker + миграции из supabase/migrations
npx supabase status          # API URL и anon key → в .env.local
```

Письма (подтверждение, восстановление пароля) локально попадают в Mailpit: http://127.0.0.1:54324.

```
content/                    контент курса (правится без изменения кода)
  course.yaml               название курса
  concepts.yaml             реестр понятий: id, «Вспомним», мини-пример, статьи справочника
  glossary/*.yaml           справочник (термины и функции с поиском)
  m02-pandas-etl/           папка модуля
    module.yaml             номер, название, описание, источники, warmupReviews
    l05-filters/            папка урока: lNN-имя (номер урока берётся из NN)

      *.svg                 схемы урока

  data/                     датасеты, доступные коду (cars.csv, cars_processed.csv, …)
  py/runner.py              общий «движок» запуска и проверки кода (браузер и Node)
  py/course.py              вспомогательные функции курса (load_numeric)

src/lib/progress/           прогресс: правила слияния, хранилище, синхронизация

```

## Как добавить урок

1. Создайте папку `content/<модуль>/lNN-короткое-имя/` (NN — номер урока в модуле).
2. Напишите `lesson.md`. Frontmatter:

   ```yaml
   ---
   id: m2-l5                      # уникальный id
   title: "Фильтрация по условиям"
   type: theory                   # theory (по умолчанию) | warmup | project | checkpoint | guide
   duration: 16                   # минут
   summary: Одно предложение о уроке.
   introduces: [pd-bool-filter]   # 1–3 новых понятия (только для theory)
   uses: [mask-combine]           # прошлые понятия урока
   files: [cars.csv]              # датасеты из public/data
   setup: |                       # выполняется перед примерами (скрыто от ученика)
     import pandas as pd
     df = pd.read_csv('cars.csv')
   sources:
     - "Workshops/02_Pandas_Cars ETL.ipynb — раздел 4"
   ---
   ```

   Разделы теоретического урока (проверяются валидатором): `## Зачем это нужно`, объяснение, 2–5 запускаемых
   примеров, `## Типичные ошибки`, `## Мини-квиз` (2–4 вопроса в блоке ```` ```quiz ````), `## Что запомнить` (3–5 пунктов).
   Каждый раздел `##` становится отдельным шагом урока.

   - Блок ```` ```python ```` — запускаемый пример; все примеры урока выполняются в общем пространстве имён по порядку.
     Метки: `norun` — только показать, `expect-error` — пример намеренно падает, `expect-warning` — намеренно выводит предупреждение.
   - Формулы — KaTeX: `$...$` и `$$...$$`. Схемы — `![подпись](schema.svg "заголовок")`.
   - Врезки: `:::info Заголовок`, `:::warning`, `:::tip`, `:::important`, `:::mistake` … `:::`.
   - Квиз: список вопросов `q`, `options`, `answer` (номер с нуля или список номеров), `explain`; `ordered: true` — не перемешивать варианты.
3. Новые понятия добавьте в `content/concepts.yaml` (с текстом для карточки «Вспомним»), термины — в `content/glossary/`.
4. Запустите `npm run validate -- --lesson <id>`, затем `npm run course-map`.
5. Если сайт запущен через `npm run dev`, перезапустите его: Next.js запоминает список страниц уроков при старте,
   и новая папка урока до перезапуска открывается с ошибкой 404 (в собранной версии такого нет).

## Как добавить задание

Задания лежат в `tasks.yaml` урока. Задание с кодом:

```yaml
- id: m2-l5-t1
  title: Объявления с ручной коробкой
  difficulty: warmup            # warmup | main | star
  introduces: [pd-bool-filter]  # ⊆ понятия урока
  uses: [bool-mask]             # ≤ 3 прошлых понятия
  statement: |
    Получите `manual` — …
  prelude: |                    # «Подготовка»: выполняется перед кодом ученика
    import pandas as pd
    df = pd.read_csv('cars.csv')   # загрузка — урок 2.1
  starter: |
    manual = ...
  solution: |
    manual = df[df['AutoTransmission'] == False]
  explanation: |                # построчное пояснение решения
    - …
  alternatives: [ ... ]         # другие верные решения (проверяются валидатором)
  hints: [направление, инструмент, почти решение]   # ровно 3
  tests: |
    m = var('manual', pd.DataFrame, 'таблицей DataFrame')
    same_frame(m, ref('manual'), 'Отобраны не те строки.')
    close(alt('n_manual'), alt_ref('n_manual'), HARDCODE_MSG)
  wrong:                        # неверные решения и ожидаемый фрагмент сообщения
    - code: |
        manual = df[df['AutoTransmission'] == 'False']
      expect: без кавычек
```

Другие виды: `kind: quiz` и `kind: predict` (поле `quiz` вместо кода), `kind: bug` («найди ошибку»).

Помощники в тестах: `var(имя, тип, описание)` — переменная ученика с проверкой типа; `ref(имя)` — значение из эталона;
`alt(имя)` / `alt_ref(имя)` — то же на **другой части данных** (70 % строк, дробные значения слегка изменены:
вписанный вручную ответ не пройдёт); `close`, `equal`, `same_array`, `same_frame` (таблицы и колонки pandas
с объяснением первого расхождения), `ensure`, `fail`, `source()`, `calls('имя')`, `no_loops()`, `axes()`,
`figures()`, `out_text()`, константа `HARDCODE_MSG`. Ошибки Python ученик видит по-русски, исходный traceback — по кнопке.

## Правила нагрузки на память

Проверяются `npm run validate`: теоретический урок вводит 1–3 понятия; в `uses` задания не больше трёх прошлых понятий,
все введены раньше; прошлые понятия — из текущего или 1–2 предыдущих модулей, а более давние — только если повторены
в разминке модуля (`warmupReviews`). Карточки «Вспомним» строятся автоматически из `uses`; давние шаги (загрузка,
очистка) вынесены в «Подготовку» с пометкой, где они изучались.

## Как устроено

- **Python в браузере:** Pyodide 314.0.7 (Python 3.14, NumPy 2.4, pandas 3.0, Matplotlib 3.10, scikit-learn 1.8)
  в модульном Web Worker; таймаут запуска 20 с, проверки — 40 с, кнопка «Остановить». Тот же `runner.py` используется
  валидатором под Node, поэтому проверка на сайте и в CI совпадает. Память движка Pyodide только растёт; если после
  выполнения она больше 1 ГБ (`PY_MEMORY_LIMIT_MB` в `src/lib/config.ts`), Python перезапускается в безопасной точке —
  перед запуском или проверкой задания, отправкой решения соревнования или запуском примера урока (предыдущие примеры
  урока при этом выполняются заново автоматически), а строка состояния объясняет причину. Если сразу после такого
  перезапуска Python снова занимает больше порога (тяжёлые библиотеки), следующий перезапуск будет только после роста
  ещё на 25 % — без перезапусков по кругу.
- **Приложение и офлайн (PWA):** сайт устанавливается как приложение — на Android и в Chrome/Edge кнопкой
  «Установить» (страница «Без интернета», `/app`, и подсказка на главной и в оглавлении), на iPhone и iPad — через
  «Поделиться → На экран „Домой“» (инструкция там же). Манифест — `src/app/manifest.ts`, иконки рисует
  `scripts/gen-icons.mjs` из логотипа. Офлайн-режим даёт service worker `public/sw.js`: страницы — «сначала сеть»
  (онлайн всё всегда свежее, без сети — сохранённая копия или страница «Нет подключения» со списком сохранённых
  уроков), файлы сборки, Pyodide, пакеты и plotly.js — «сначала кэш» (в адресах есть версия), `/data`, `/py`,
  `/workers` — одна копия каждого файла. Вход, прогресс и соревнования никогда не кэшируются; решения без сети
  копятся и отправляются, когда она появится. Открытые уроки сохраняются сами, а кнопка «Скачать курс» на странице
  «Без интернета» сохраняет весь курс (около 160 МБ на устройстве: страницы, данные, Python, seaborn и plotly) — список файлов
  строится при сборке (`/offline-files.json`). На телефонах, планшетах и компьютерах с памятью до 4 ГБ порог
  перезапуска Python ниже — 640 МБ (`PY_MEMORY_LIMIT_MOBILE_MB`). Выключение — DEPLOY.md, раздел 10.
  Цвета системных полос телефона: строка состояния сверху (`<meta name="theme-color">`) следует теме сайта, в том
  числе выбранной кнопкой (`ThemeColorSync`); нижнюю панель Android у установленного приложения Chrome красит в
  `theme_color` манифеста и тёмного варианта не знает, поэтому `theme_color` в манифесте нет — панель следует теме
  телефона.
- **Код на телефоне:** на сенсорном экране, пока редактор в фокусе, прямо над экранной клавиатурой появляется панель
  символов Python (`src/components/code/MobileCodeKeys.tsx`): отступ и его отмена, скобки и кавычки (парой, как при
  наборе: курсор встаёт между ними, а закрывающую перескакивает), `: = . , _ #`, знаки операций, стрелки курсора,
  «Отменить» и «Повторить». Место панели считается по `window.visualViewport` (видимая часть экрана над клавиатурой),
  кнопки не забирают фокус у редактора, поэтому клавиатура не закрывается. На компьютере панели нет.
- **Seaborn и Plotly:** их нет в сборке Pyodide, поэтому движок ставит `seaborn==0.13.2` и `plotly==7.1.0` через micropip
  с PyPI при первом `import` (версии закреплены в `public/workers/py-engine.mjs`). Интерактивные графики рисует
  plotly.js 4.1.1 с jsDelivr — та же версия, что встроена в plotly 7.1.0. Задания с графиками проверяются по объектам
  (Matplotlib — оси, линии, столбцы; Plotly — ряды `fig.data`, подсказки, макет), а не по картинке.
- **Аккаунты и логины:** при регистрации ученик выбирает логин (латиница, 3–20 символов, уникальный без учёта регистра;
  `src/lib/username.ts` и ограничение в базе). Входить можно по логину или по почте. В углу экрана и в таблице лидеров
  виден логин, а не почта; у аккаунтов, созданных до логинов, в углу — «Придумайте логин» со ссылкой на форму в профиле.
  Вход по логину: функция базы `login_email` возвращает почту только при верном пароле, после 10 неудачных попыток за
  15 минут вход по этому логину приостанавливается (вход по почте работает как обычно). Восстановление пароля — только по
  почте: по логину адрес не раскрывается (миграция `20261121000002_usernames.sql`).
- **Прогресс:** гость — localStorage; после входа — локальный кэш + таблица `progress` в Supabase. Изменения
  отправляются с задержкой, при обрыве сети копятся и уходят после восстановления связи; слияние одинаковое на
  клиенте (TypeScript) и в базе (SQL): статус «сильнейший», счётчики — максимум, код — более свежий. Несколько вкладок
  синхронизируются через BroadcastChannel; при входе гостевой прогресс переносится в аккаунт («Перенесено N решённых задач»).
- **Безопасность:** доступ к данным — только через RLS (каждый видит и меняет только своё), пароли хранит Supabase Auth,
  удаление аккаунта — серверная функция. Секретных ключей в клиентском коде и в репозитории нет (`.env.example` вместо `.env`).
  На одного пользователя — не больше 3000 записей прогресса и 10 МБ данных (триггер в базе). После входа сайт переходит
  только по путям самого сайта (`safeNext` в `src/lib/url.ts`). Заголовки запрещают встраивать сайт в чужие страницы
  (`X-Frame-Options`, `frame-ancestors`), включают HSTS и Permissions-Policy; заголовка `X-Powered-By` нет.
  Аудит безопасности с проверками атаками — в TEST_REPORT.md.
- **Соревнования:** решение ученика выполняется в браузере, режим `submission` движка собирает таблицу прогнозов и
  проверяет формат (все ID, без пропусков; для соревнования с классами — только классы из списка). На сервер уходят
  только ответы: функция `/api/competitions/[id]/submit` ещё раз проверяет формат, лимит (10 за 24 часа) и считает
  метрику по ответам из `private/` — MAE по ценам (соревнование 1) или долю верных по классам (соревнование 2); ответы
  попадают только в серверную функцию. Настройки соревнования — метрика, её направление, формат ID и ответов, baseline —
  в `src/lib/competitions/registry.ts`; в базе для любой метрики хранится величина «меньше — лучше» (MAE или доля
  ошибок), поэтому таблица лидеров одна для всех соревнований. Ученик с аккаунтом передаёт токен Supabase; результат записывается служебным ключом в таблицы
  `competition_*`, закрытые RLS для всех, кроме сервера (иначе любой вписал бы себе лучший результат). В таблице лидеров
  участники видны по логинам; идентификаторы пользователей в браузер не уходят. Валидатор
  контента проверяет, что заготовка даёт ровно baseline из реестра, а эталон из `private/` его обгоняет.
- **Датасеты:** `cars.csv` — исходные объявления; `cars_processed.csv` — результат модуля 2, собирается
  `npm run data:build` тем же кодом, что разбирается в уроках, и совпадает с файлом курса `Workshops/cars_processed.csv`;
  `titanic.csv` и `adult.csv` (из материалов ODS) — для мини-проектов модулей 3, 4 и 7; `diabetes.csv` — набор Diabetes
  из scikit-learn (`load_diabetes(scaled=False)`, 442 пациента) — для мини-проектов модулей 5 и 6. Отдельный файл, а не
  загрузка из sklearn, нужен защите от вписанных ответов: проверка повторяет решение на изменённой копии файла.
  `competition_cars_train.csv` и `competition_cars_test.csv` — соревнование 1. Ответов к исходному `cars_test.csv` в
  материалах нет (они были на Kaggle), поэтому обе части собраны из `Workshops/basic competitions/cars_train.csv`
  скриптом `scripts/data/build_competition_cars.py` (`npm run data:build`): повторы целиком в одной части, в проверочной —
  цены 1 000–500 000, ответы — в `private/competitions/cars-price/answers.json`. Соревнование 2 — скрытая половина
  картинок «Zero-shot классификации изображений»: векторы CLIP и группа/язык без классов под новыми ID
  (`competition_zs_test.csv`, `.npy`), ответы — в `private/competitions/zero-shot/answers.json`
  (`scripts/hf/build_hf_data.py competition`).
  `qa_train.csv`, `qa_test.csv` и `qa_gigachat_baseline.csv` — вопросы соревнования «QA» и прогнозы базового решения
  (`Workshops/basic competitions`); правильных ответов теста в материалах нет, поэтому модуль 10 оценивает решения на
  87 вопросах с ответами и по итогу 65,8 % из ноутбука базового решения.
  Соревнование 3 проверяет ответы на те же 786 вопросов теста. Правильных ответов теста в материалах нет, поэтому их
  разметили составители сайта: разметка с уверенностью и комментариями — `private/competitions/qa/разметка_теста_QA_на_проверку.csv`,
  проверенная версия с правками проверяющего (столбцы «Исправление» и «Ваш комментарий») — `разметка_теста_QA_проверено.csv`, скрытые ответы `private/competitions/qa/answers.json` собирает
  `python3 scripts/llm/build_qa_competition.py`. Вопросы о 2025–2026 годах и испорченные вопросы не оцениваются. Форма
  соревнования, кроме кода, принимает файл CSV (`upload: true` в реестре): ответы, полученные от GigaChat в Colab.

Ссылка «Нашли ошибку?» задаётся переменной `NEXT_PUBLIC_REPORT_BUG_URL` (или константой в `src/lib/config.ts`).
